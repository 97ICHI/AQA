:::why
Тест, который вы копируете, но не понимаете, невозможно починить, когда он упадёт. В этом уроке мы разберём короткий тест магазина построчно: что делает каждая строка, когда она выполняется и что будет, если её убрать.
:::

## Тест, который разбираем

```ts tests/search.spec.ts
import { test, expect } from '@playwright/test';                 // 1

test('поиск находит кружку', async ({ page }) => {                // 2
  await page.goto('/');                                           // 3
  await page.getByLabel('Поиск товара').fill('Кружка');           // 4
  await page.getByRole('button', { name: 'Найти' }).click();      // 5
  await expect(page).toHaveURL(/q=/);                             // 6
  await expect(page.getByRole('listitem')).toHaveCount(1);        // 7
  await expect(page.getByRole('heading', { name: 'Кружка' })).toBeVisible(); // 8
});
```

### Строка 1 — импорт

`test` и `expect` берутся из пакета раннера `@playwright/test`. Это обычный [[es-module|импорт модуля]] TypeScript. Без него в файле нет ни функции `test`, ни проверок.

### Строка 2 — объявление теста

`test(название, функция)` регистрирует тест. Название попадает в отчёт, поэтому пишите его как ожидаемое поведение: «поиск находит кружку», а не «test1».

Функция помечена `async`: внутри будут асинхронные операции, которые нужно дожидаться через `await`. Подробно об этом — в уроке [[async-await|про async/await]].

`{ page }` — это деструктуризация объекта fixtures: раннер передаёт в функцию объект с готовыми объектами, а мы берём из него `page`. Раннер создаёт [[pw-page|страницу]] перед тестом в новом [[browser-context|контексте браузера]] и закрывает её после теста.

### Строка 3 — открыть страницу

`page.goto('/')` открывает адрес. Путь `/` дополняется [[base-url|baseURL]] из конфигурации. `goto` по умолчанию ждёт события `load` — страница загружена вместе со скриптами и стилями.

### Строка 4 — найти поле и ввести текст

`page.getByLabel('Поиск товара')` — [[locator|локатор]]: описание «поле, подписанное текстом „Поиск товара“». В момент создания он ничего не ищет. Поиск происходит, когда вызывается действие `fill('Кружка')`: Playwright находит элемент, ждёт, пока он станет видимым и доступным для ввода, очищает поле и вводит текст.

### Строка 5 — нажать кнопку

`getByRole('button', { name: 'Найти' })` — кнопка с доступным именем «Найти». `click()` перед нажатием [[auto-waiting|ждёт готовности]] элемента. Форма отправляется, браузер переходит на `/?q=Кружка`.

### Строки 6–8 — проверки

Каждая `expect(...)` — [[web-first-assertion|ожидающая проверка]]: Playwright повторяет её, пока условие не выполнится или не истечёт таймаут (в нашем runner — 3 с).

- `toHaveURL(/q=/)` — адрес содержит параметр поиска: форма действительно отправилась;
- `toHaveCount(1)` — в списке ровно одна карточка;
- `toBeVisible()` — заголовок карточки «Кружка» виден.

Порядок важен: проверка URL гарантирует, что мы смотрим на результаты поиска, а не на каталог, где карточек шесть.

## Зачем `await` в каждой строке

Каждое действие и каждая проверка возвращают Promise. `await` говорит: «дождись результата, потом иди дальше». Если его забыть, тест не ждёт: следующая строка начинается, пока клик ещё не выполнен, а тест может закончиться раньше, чем завершится проверка.

:::mistake
**Пропущенный `await` перед `expect` или действием.** Такой тест ведёт себя непредсказуемо: в одном прогоне он проходит, в другом падает со странным сообщением вроде `Received: ""` — страница к тому моменту уже закрыта. Ошибку прячет то, что код «выглядит правильно». Правило простое: перед каждым `page.…` действием и каждым `expect(локатор)` стоит `await`. Включите в проекте правило линтера `@typescript-eslint/no-floating-promises` — оно находит такие строки до запуска.
:::

:::deep Подготовка, действие, проверка
Почти любой тест раскладывается на три части: *подготовка* (открыть страницу, войти, создать данные), *действие* (то, что проверяем) и *проверка* (наблюдаемый результат). Эту схему называют Arrange–Act–Assert. В UI-тестах между действиями часто стоят промежуточные проверки — как `toHaveURL` выше. Они не «лишние»: они фиксируют, что предыдущий шаг завершился, прежде чем начинать следующий, и делают падение понятнее.
:::

:::tech Что ещё можно взять из fixtures
Кроме `page` раннер передаёт и другие fixtures: `context` (контекст браузера этого теста), `browser` (общий браузер воркера), `request` (HTTP-клиент для API), `baseURL` (строка из конфигурации). Вторым аргументом функции теста приходит `testInfo` — сведения о текущем тесте: название, номер повтора, папка для вложений. Берите только то, что нужно: `async ({ page, request }) => …`.
:::

:::interview
**Вопрос:** «Что происходит при `page.getByRole('button', { name: 'Найти' })` без действия?» **Ответ по сути:** ничего не ищется. Локатор — ленивое описание; поиск выполняется при каждом действии или проверке заново. Поэтому локатор можно создать заранее и переиспользовать, даже если страница между действиями перерисовалась.
:::
