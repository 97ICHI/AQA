:::why
Корзина — это список позиций, заказ — набор полей с вложенными данными о покупателе, ответ API — объект с массивом внутри. Чтобы проверить такие данные в тесте, нужно уметь добраться до нужного значения: «второй товар», «город покупателя», «сколько позиций».
:::

## Массив: список по порядку

[[js-array|Массив]] хранит значения в определённом порядке. Записывается в квадратных скобках через запятую:

```ts tests/data/catalog.ts
const titles = ['Блокнот A5', 'Ручка', 'Наушники Pulse'];

titles[0];        // 'Блокнот A5' — нумерация с нуля
titles[2];        // 'Наушники Pulse'
titles[3];        // undefined — такого элемента нет
titles.length;    // 3
```

Номер элемента называется индексом и **начинается с нуля**. Последний элемент — `titles[titles.length - 1]` или короче `titles.at(-1)`. Обращение за пределы массива не вызывает ошибки, а возвращает `undefined`.

Добавить элемент в конец — `titles.push('Чехол')`. Проверить, есть ли значение, — `titles.includes('Ручка')`.

## Объект: значения с именами

[[js-object|Объект]] хранит значения под именами — **свойствами** (полями). Записывается в фигурных скобках: `имя: значение`.

```ts tests/data/order.ts
const order = {
  id: 17,
  status: 'paid',
  items: [
    { title: 'Блокнот A5', price: 390, qty: 2 },
    { title: 'Ручка', price: 120, qty: 1 },
  ],
  customer: { name: 'Анна', city: 'Казань' },
};

order.status;              // 'paid'
order.items.length;        // 2
order.items[0].title;      // 'Блокнот A5'
order.customer.city;       // 'Казань'
```

Свойство читается через точку: `order.status`. Если имя хранится в переменной, используют квадратные скобки: `order['status']`. Вложенные данные читаются цепочкой слева направо: `order.items[0].title` — «у заказа взять позиции, у них первую, у неё название».

Изменить свойство — присвоить: `order.status = 'shipped'`. Чтение отсутствующего свойства даёт `undefined`, а чтение свойства *у* `undefined` — ошибку выполнения.

## Такие же данные приходят с сервера

Ответ API почти всегда — [[json|JSON]]: текстовая запись тех же объектов и массивов. После разбора (`JSON.parse`) с ним работают точно так же: `body.items[0].price`.

Чтение по индексу и через точку вернуло нужные значения, а `push` добавил позицию в конец — массив стал из трёх элементов.

`order.items[5]` — `undefined`: такого элемента нет, но ошибки нет. Это важно: тест, который берёт «шестой элемент» по ошибке, не упадёт сразу, а получит `undefined` и упадёт дальше в неожиданном месте.

`order.customer.phone` — **ошибка типа** `TS2339: Property 'phone' does not exist`: TypeScript знает форму объекта и видит, что такого поля нет. При выполнении получилось `undefined`. Опечатку в имени поля TypeScript ловит до запуска — это одна из главных причин писать тесты на нём.

`order.items[5].title` уже бросило бы во время выполнения `TypeError: Cannot read properties of undefined (reading 'title')`. При этом TypeScript по умолчанию *не* сообщает об этом заранее: он не знает, сколько элементов будет в массиве.
:::

## Задание

```widget
{"type":"exercise","id":"m3-obj-order-summary"}
```

В заготовке задания есть строки `interface Order { … }` — это описание формы заказа для TypeScript. Сейчас его достаточно прочитать; писать такие описания будем в уроке [[interface-ts|про типы]].

:::mistake Индекс с единицы
`order.items[1]` — вторая позиция, не первая. Если тест проверяет «первый товар в корзине» и берёт `[1]`, на корзине из одного товара он получит `undefined`.
:::

:::deep Копия или та же самая корзина
Присваивание `const copy = order` не копирует объект: обе переменные указывают на одни и те же данные, и изменение через `copy` видно через `order`. Неглубокая копия — `{ ...order }` или `[...items]`; полная — `structuredClone(order)`. В тестовых данных это частая причина «тест испортил данные соседнему тесту».
:::

:::tech Безопасное чтение
`order.customer?.city` — опциональная цепочка: если `customer` равно `null` или `undefined`, результат — `undefined` вместо ошибки. Удобно при чтении, но в проверке не стоит прятать так отсутствие обязательного поля: лучше, чтобы тест явно упал.
:::

:::interview
**Вопрос:** «Что вернёт обращение к несуществующему индексу массива?» **Ответ по сути:** `undefined`, без ошибки. Ошибка появится, когда у этого `undefined` попытаются прочитать свойство. Поэтому в тестах полезно сначала проверить длину массива, а потом элементы.
:::
