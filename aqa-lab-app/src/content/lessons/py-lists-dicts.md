Ответ API, строка из базы, тестовый пользователь — всё это структуры: объекты с полями и списки объектов. В Python для них есть два главных инструмента — список и словарь. Почти любой тест на Python читает или строит такие структуры.

## Список

[[python-list|Список]] (`list`) — упорядоченная изменяемая коллекция. Пишется в квадратных скобках:

```py tests/data.py
titles = ["Наушники Pulse", "Блокнот A5", "Кружка"]

print(titles[0])        # Наушники Pulse — индексы с нуля
print(titles[-1])       # Кружка — с конца
print(len(titles))      # 3
print("Кружка" in titles)  # True

titles.append("Лампа")  # добавить в конец
titles.remove("Кружка") # удалить первое совпадение
print(titles[1:3])      # срез: элементы 1 и 2
```

Обращение к несуществующему индексу (`titles[10]`) — ошибка `IndexError`. Списки можно сортировать: `sorted(titles)` возвращает новый список, `titles.sort()` сортирует на месте.

## Словарь

[[python-dict|Словарь]] (`dict`) хранит пары «ключ → значение». Пишется в фигурных скобках. Это прямой аналог JSON-объекта:

```py tests/data.py
order = {
    "id": 101,
    "status": "paid",
    "promo_code": None,
}

print(order["status"])          # paid
order["status"] = "shipped"     # изменить
order["comment"] = "у двери"    # добавить новый ключ
print(order.get("discount"))    # None — ключа нет, ошибки нет
print(order.get("discount", 0)) # 0 — значение по умолчанию
print("id" in order)            # True — проверка ключа
```

Разница между `order["x"]` и `order.get("x")` важна в тестах. Квадратные скобки падают с `KeyError`, если ключа нет, — это хорошо, когда поле обязательно: тест сразу скажет, чего не хватает. `.get()` возвращает `None` и подходит для необязательных полей.

Перебрать словарь можно по ключам (`for key in order`), по значениям (`order.values()`) и по парам (`for key, value in order.items()`).

## Вложенные структуры

Реальный заказ — это словарь, внутри которого словари и списки:

```py tests/order.py
order = {
    "id": 101,
    "user": {"id": 1, "email": "anna@example.test"},
    "items": [
        {"sku": "PULSE-01", "price": 4990, "qty": 1},
        {"sku": "NOTE-A5", "price": 390, "qty": 2},
    ],
}

print(order["user"]["email"])          # anna@example.test
print(order["items"][1]["sku"])        # NOTE-A5
print(len(order["items"]))             # 2
```

Читается слева направо: из заказа взять `items`, из списка — элемент 1, из него — `sku`.

## Изменяемость и копии

Списки и словари изменяемы. Присваивание не копирует их, а создаёт второе имя для того же объекта:

```py tests/copy.py
base = {"status": "new"}
other = base              # то же самое
other["status"] = "paid"
print(base["status"])     # paid — изменился и base

import copy
safe = copy.deepcopy(base)  # независимая копия, включая вложенные структуры
```

В тестах это частый источник «загадочных» падений: общий словарь тестовых данных изменили в одном тесте, и он «испортился» для следующего. Шаблонные данные копируют или создают заново для каждого теста.

:::deep Кортеж и множество
`tuple` — неизменяемый список: `point = (10, 20)`. Его удобно возвращать из функции, когда значений несколько: `return good, bad`. `set` — множество уникальных значений без порядка: `set(skus)` убирает дубли, а `{"a", "b"} == {"b", "a"}` — `True`. Множества полезны, когда в проверке не важен порядок: `assert set(actual) == {"PULSE-01", "NOTE-A5"}`.
:::

:::tech Сравнение структур
`==` сравнивает списки и словари по содержимому, рекурсивно: два словаря равны, если у них одинаковые ключи и равные значения, порядок ключей не важен. У списков порядок важен. pytest при падении `assert actual == expected` показывает подробную разницу: какие ключи отличаются и какие элементы лишние.
:::

:::interview
**Вопрос:** «Чем `d["key"]` отличается от `d.get("key")` и что выбрать в тесте?» **Ответ по сути:** `d["key"]` бросает `KeyError`, если ключа нет; `get` возвращает `None` или значение по умолчанию. Для обязательных полей ответа лучше `d["key"]` или явная проверка `"key" in d` — тест упадёт с понятной причиной. `get` — для необязательных полей.
:::
