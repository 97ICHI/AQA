:::why
UI-тест ищет на странице кнопки, поля и тексты. Чтобы искать надёжно, нужно видеть страницу так, как её видит браузер: не картинкой, а деревом элементов, у каждого из которых есть роль и имя. Тогда локаторы получаются понятными и не ломаются от смены оформления.
:::

## От HTML к дереву

Сервер присылает браузеру текст HTML. Вот упрощённая карточка товара из учебного магазина:

```html
<ul aria-label="Товары">
  <li class="card" id="product-3">
    <h2>Блокнот A5</h2>
    <p>390 ₽</p>
    <button type="button" class="add-to-cart">В корзину</button>
  </li>
</ul>
```

Браузер разбирает этот текст и строит [[dom|DOM]] — дерево объектов. У каждого элемента есть родитель, дети, атрибуты и текст. Кнопка — ребёнок `li`, `li` — ребёнок `ul`. Скрипты страницы меняют именно DOM: когда вы нажимаете «В корзину», скрипт меняет текст счётчика в шапке, и HTML-исходник страницы тут ни при чём.

Тест тоже работает с DOM — с текущим состоянием страницы, а не с тем, что пришло от сервера.

## Роль и доступное имя

Для людей, которые пользуются экранными дикторами, браузер строит ещё одно дерево — [[accessibility-tree|дерево доступности]]. В нём нет классов и `id`, зато у каждого значимого элемента есть:

- [[aria-role|роль]] — что это такое: `button`, `link`, `heading`, `listitem`, `textbox`. Роль обычно следует из тега: `<button>` — кнопка, `<a href>` — ссылка, `<h2>` — заголовок;
- [[accessible-name|доступное имя]] — как это называется: текст кнопки, подпись `<label>` у поля, `alt` у картинки, атрибут `aria-label`.

Та же карточка в дереве доступности:

```text
list "Товары"
  listitem
    heading "Блокнот A5"
    text "390 ₽"
    button "В корзину"
```

Это то, что видит пользователь: «список Товары, в нём заголовок Блокнот A5 и кнопка В корзину». Классы `card` и `add-to-cart` пользователю не видны — и могут поменяться при новой вёрстке.

## Локатор по роли и имени

[[locator|Локатор]] — описание того, как найти элемент. Самый надёжный вид локатора ищет по роли и имени — как пользователь:

```ts tests/catalog.spec.ts
const card = page.getByRole('listitem').filter({ hasText: 'Блокнот A5' });
await card.getByRole('button', { name: 'В корзину' }).click();
```

Сравните с локатором по CSS-классу:

```ts tests/catalog.spec.ts
await page.locator('#product-3 .add-to-cart').click();
```

Второй локатор зависит от `id` и класса. Дизайнер переименует класс — тест упадёт, хотя магазин работает. В учебном магазине это вариант «Новая вёрстка»: другие классы и `id`, те же роли и тексты. Тест с `getByRole` его выдерживает, тест с CSS — нет.

:::note
Если у элемента нет понятной роли или имени, это часто проблема доступности самой страницы. Например, кнопка-иконка «+» без `aria-label` не имеет имени ни для теста, ни для экранного диктора. Хороший тестировщик сообщает об этом как о дефекте.
:::

В лаборатории — фрагмент каталога. Найдите кнопку «В корзину» у «Наушники Pulse Pro», затем кнопку добавления кабеля — у неё видимый текст «+», но есть `aria-label`. Посмотрите, какие роли и имена показывает лаборатория.
:::

```widget
{"type":"locator-lab","task":"Найдите кнопку «В корзину» в карточке «Наушники Pulse Pro», а затем кнопку добавления кабеля по её доступному имени."}
```

:::happened
`page.getByRole('button', { name: 'В корзину' })` находит несколько кнопок — по одной в каждой карточке. Чтобы выбрать нужную, сначала сужают поиск до карточки: `getByRole('listitem').filter({ hasText: 'Наушники Pulse Pro' })`. Кнопка кабеля на экране выглядит как «+», но её доступное имя — «Добавить кабель в корзину» из `aria-label`: роль и имя берутся из дерева доступности, а не из того, что нарисовано.
:::

## Дерево — это рекурсия

Поиск по роли — обход дерева: проверить узел, затем его детей, затем их детей. Напишите такой поиск сами на упрощённой модели страницы, где каждый узел — `{ role, name, children }`.

```widget
{"type":"exercise","id":"m4-find-by-role"}
```

:::deep Как на самом деле вычисляется имя
Алгоритм доступного имени описан в спецификации W3C и учитывает много источников по приоритету: `aria-labelledby`, `aria-label`, связанный `<label>`, `alt`, `title`, текст содержимого. Не у всех ролей имя берётся из содержимого: у кнопки и ссылки — да, у списка и элемента списка — нет. Поэтому `getByRole('listitem', { name: 'Блокнот A5' })` карточку не найдёт, а `getByRole('listitem').filter({ hasText: 'Блокнот A5' })` — найдёт. Лаборатория в этом уроке — учебная модель с упрощённым алгоритмом; настоящий Playwright использует полный.
:::

:::tech Где посмотреть дерево доступности
В Chrome DevTools: вкладка Elements → панель Accessibility показывает роль и имя выбранного элемента. В Playwright есть `expect(locator).toMatchAriaSnapshot()` — проверка структуры дерева доступности в виде YAML, и генератор кода `npx playwright codegen`, который сам предлагает локаторы по роли.
:::

:::interview
**Вопрос:** «Чем DOM отличается от HTML?» **Ответ по сути:** HTML — текст, который пришёл от сервера; DOM — дерево объектов, которое браузер построил из него и которое меняют скрипты. Тесты работают с текущим DOM. Для поиска элементов лучше опираться на дерево доступности — роль и доступное имя: они отражают то, что видит пользователь, и устойчивы к смене вёрстки.
:::
