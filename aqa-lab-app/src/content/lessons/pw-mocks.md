:::why
Некоторые ситуации трудно получить на настоящем сервере: ошибку `500`, пустой склад, медленный ответ, редкие данные. Playwright умеет перехватить запрос страницы и ответить вместо сервера. Это мощный приём, но у него есть цена: подменённая часть системы перестаёт проверяться. В этом уроке — как подменять и как помнить об этой цене.
:::

## Перехват запросов страницы

[[network-interception|Перехват сети]] включается методом `page.route(url, handler)`. Каждый запрос страницы, адрес которого совпал с шаблоном, попадает в `handler` вместо сервера. В обработчике запрос `route` можно:

- **ответить самому** — `route.fulfill({ status, json })`: сервер вообще не получит запрос;
- **пропустить дальше** — `route.continue()`: запрос уйдёт на сервер, можно поменять заголовки или тело;
- **оборвать** — `route.abort()`: для страницы это выглядит как сетевой сбой;
- **сходить на сервер и изменить ответ** — `route.fetch()`, затем `route.fulfill({ response, json })`.

Шаблон `'**/api/cart'` — glob: `**` означает «любое начало адреса». Можно передать и регулярное выражение.

```ts tests/cart-errors.spec.ts
import { test, expect } from '@playwright/test';

test('ошибка сервера при добавлении показывается пользователю', async ({ page }) => {
  await page.route('**/api/cart', (route) =>
    route.fulfill({ status: 500, json: { error: 'склад недоступен' } }));

  await page.goto('/');
  await page.getByRole('listitem').filter({ hasText: 'Блокнот A5' })
    .getByRole('button', { name: 'В корзину' }).click();
  await expect(page.getByRole('status')).toHaveText('Ошибка: склад недоступен');
});
```

`page.route` ставят **до** действия, которое отправляет запрос. Перехват действует только для этой страницы (для всего контекста — `context.route`) и только для запросов браузера: запросы fixture `request` он не трогает.

Такой тест проверяет **интерфейс**: как страница реагирует на ошибку. Сервер в этом тесте не участвует — это [[stub|заглушка]] ответа.

## Что перестаёт проверяться

Подменим успешный ответ и запустим тест на магазине, где товар на самом деле не добавляется в корзину.

```widget
{"type":"playground","lang":"pw","title":"Подменённый ответ на магазине с дефектом","variant":"cart-not-add","code":"import { test, expect } from '@playwright/test';\n\ntest('добавление в корзину (ответ сервера подменён)', async ({ page }) => {\n  await page.route('**/api/cart', (route) =>\n    route.fulfill({ json: { items: [], total: 390, count: 1 } }));\n  await page.goto('/');\n  await page.getByRole('listitem').filter({ hasText: 'Блокнот A5' })\n    .getByRole('button', { name: 'В корзину' }).click();\n  await expect(page.getByTestId('cart-count')).toHaveText('1');\n});\n","recorded":{"variant":"Дефект: товар не добавляется в корзину","output":"Магазин: Дефект: товар не добавляется в корзину\n✓ добавление в корзину (ответ сервера подменён) (278 мс)"}}
```

:::happened
Тест прошёл, хотя магазин сломан. Подменённый ответ сказал странице «count: 1», и страница честно это показала. Настоящий сервер в тесте не участвовал, поэтому его дефект не мог проявиться.

Это не ошибка Playwright, а свойство любой подмены: **[[mocking|mock]] проверяет только то, что осталось настоящим**. Тест с подменой ответа `/api/cart` проверяет страницу, но ничего не говорит о корзине на сервере. Поэтому рядом с mock-тестами всегда нужны тесты без подмены — UI или API, — которые проверяют настоящий сервер.
:::

## Частичная подмена

Иногда нужен настоящий ответ, но с одним изменённым полем — например, чтобы проверить, как страница покажет большое число. Для этого запрос отправляют на сервер через `route.fetch()`, а странице отдают изменённую копию ответа — это [[partial-mock|частичная подмена]].

```widget
{"type":"playground","lang":"pw","title":"Частичная подмена: настоящий ответ, одно поле изменено","variant":"ok","code":"import { test, expect } from '@playwright/test';\n\ntest('частичная подмена: настоящий ответ, но count = 99', async ({ page }) => {\n  await page.route('**/api/cart', async (route) => {\n    const response = await route.fetch();          // запрос уходит на настоящий сервер\n    const json = await response.json();\n    await route.fulfill({ response, json: { ...json, count: 99 } });\n  });\n  await page.goto('/');\n  await page.getByRole('listitem').filter({ hasText: 'Кружка' })\n    .getByRole('button', { name: 'В корзину' }).click();\n  await expect(page.getByTestId('cart-count')).toHaveText('99');\n  await page.goto('/cart');                         // а сервер честно хранит 1 кружку\n  await expect(page.getByTestId('cart-count')).toHaveText('1');\n});\n","recorded":{"variant":"Исправный магазин","output":"Магазин: Исправный магазин\n✓ частичная подмена: настоящий ответ, но count = 99 (355 мс)"}}
```

:::happened
После клика страница показала `99`: так ей сказал изменённый ответ. Но запрос дошёл до сервера, и там в корзине одна кружка. После перехода на `/cart` страница загрузилась заново (её HTML собирает сервер), и счётчик стал настоящим — `1`. Частичная подмена оставляет сервер в работе, но страница всё равно видит то, что подставил тест.
:::

## Когда подменять

| Подменять оправдано | Подменять не нужно |
|---|---|
| ошибки `500`, `503`, обрывы сети | основной сценарий «добавить → оформить» |
| редкие данные: пустой список, очень длинное название | проверка суммы, статуса, прав доступа |
| внешние сервисы: оплата, доставка, карты | всё, что тест должен доказать о сервере |
| медленный ответ для проверки индикатора загрузки | — |

:::mistake Мокнуть всё ради стабильности
Если тест нестабилен, подмена всех ответов сделает его зелёным, но он перестанет проверять систему. Сначала найдите причину нестабильности. Подмена — инструмент для **недоступных** сценариев, а не способ заглушить проблему.
:::

:::deep Mock устаревает вместе с API
Подменённый ответ — копия контракта на момент написания теста. Если сервер переименует поле `count`, mock-тест останется зелёным, а настоящая страница сломается. Защита — [[contract-testing|контрактные проверки]] настоящего API и как можно меньше полей в подмене: только те, что нужны тесту. Ещё один вариант — записать настоящие ответы в файл [[har|HAR]] и воспроизводить их через `page.routeFromHAR(path)`; запись нужно обновлять, когда меняется API.
:::

:::tech Порядок и снятие перехватов
Если несколько `route` подходят к одному запросу, сработает добавленный **последним**; `route.fallback()` передаёт запрос предыдущему обработчику. Снять перехват — `page.unroute(url)` или `page.unrouteAll()`. Ожидать ответ, не подменяя его, — `page.waitForResponse('**/api/cart')`: так проверяют, что страница действительно отправила запрос. Для WebSocket есть отдельный `page.routeWebSocket`.
:::

:::interview
**Вопрос:** «Когда вы мокаете ответы в UI-тестах и чем это опасно?» **Ответ по сути:** подменяю, чтобы получить трудновоспроизводимые состояния (ошибки сервера, пустые и граничные данные, внешние сервисы). Опасность — подменённая часть не проверяется: mock-тест пройдёт при сломанном сервере и при изменённом контракте. Поэтому основные сценарии проверяю без подмены, а mock держу минимальным и сверяю с контрактом API.
:::
