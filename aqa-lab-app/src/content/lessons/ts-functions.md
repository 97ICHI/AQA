:::why
Одна и та же проверка часто нужна во многих тестах: посчитать сумму корзины, сформировать email тестового пользователя, применить скидку. Если копировать код, ошибку придётся исправлять в десяти местах. Функция даёт куску кода имя, и его можно вызывать сколько угодно раз с разными данными.
:::

## Объявление и вызов

[[js-function|Функция]] — именованный блок кода, который получает входные значения и возвращает результат.

```ts tests/helpers/money.ts
function applyDiscount(price: number, percent: number): number {
  const discount = price * percent / 100;
  return price - discount;
}

applyDiscount(1000, 10);   // 900
applyDiscount(390, 0);     // 390
```

Разберём по частям:

- `function applyDiscount` — объявление функции с именем `applyDiscount`.
- `(price: number, percent: number)` — **параметры**: имена для входных значений. В TypeScript у каждого параметра указан тип.
- `: number` после скобок — тип **возвращаемого значения**.
- `return` — вернуть результат и сразу выйти из функции. Код после `return` не выполняется.

Сама по себе запись `function …` ничего не выполняет. Код внутри работает только при **вызове**: `applyDiscount(1000, 10)`. Значения в скобках при вызове называются **аргументами**: при этом вызове `price` равно `1000`, `percent` — `10`.

## Что даёт TypeScript

Типы параметров защищают от неверного вызова: `applyDiscount('1000', 10)` — ошибка типа, код даже не запустится. Тип результата защищает от ошибки внутри функции: если забыть `return`, TypeScript скажет, что функция с типом `number` должна что-то вернуть.

Функция без `return` возвращает `undefined`. Её тип результата — `void` («ничего полезного не возвращает»): так пишут, например, функции, которые только печатают в журнал.

## Параметры по умолчанию и необязательные

```ts tests/helpers/users.ts
function testEmail(name: string, domain: string = 'example.test'): string {
  return `${name}-${Date.now()}@${domain}`;
}

testEmail('anna');                 // 'anna-1767…@example.test'
testEmail('anna', 'shop.test');    // 'anna-1767…@shop.test'
```

Значение после `=` подставляется, если аргумент не передан. Такая функция пригодится для уникальных тестовых данных: каждый вызов даёт новый email.

## Функция и проверка

Тест — это тоже функция: `test('название', () => { … })`. Внутри — вызов проверяемого кода и сравнение результата с ожиданием. В тренажёре для сравнения есть `expectEq(получено, ожидалось)`: если значения различаются, проверка падает с сообщением «ожидалось …, получено …».

Запустите код. Затем внесите в `applyDiscount` дефект — например, замените `price - discount` на `price - percent` — и посмотрите, какие проверки это заметят.
:::

'OK  ' : 'FAIL';\n  console.log(`${mark} ${name}: ожидалось ${expected}, получено ${actual}`);\n}\n\ncheck('10% от 1000', applyDiscount(1000, 10), 900);\ncheck('0% от 390', applyDiscount(390, 0), 390);\ncheck('50% от 4990', applyDiscount(4990, 50), 2495);\ncheck('100% от 120', applyDiscount(120, 100), 0);\n"}

:::happened
Функция `applyDiscount` вызывается четыре раза с разными аргументами. Функция `check` сравнивает результат с ожиданием и печатает `OK` или `FAIL` — это самодельная версия того, что делают `expect` в Playwright и `expectEq` в тренажёре.

С дефектом `price - percent` проверка «0% от 390» всё равно проходит: `390 - 0 = 390`. А «10% от 1000» падает: `1000 - 10 = 990`. Вывод: один удачный случай ещё не доказывает, что функция верна. Нужны данные, на которых разные ошибки дают разный результат.
:::

:::mistake Ожидание, посчитанное той же формулой
`expectEq(applyDiscount(1000, 10), 1000 - 1000 * 10 / 100)` — ожидание вычислено тем же способом, что и в коде. Если формула в коде неверна, неверно и ожидание. Ожидаемые значения в тестах пишут готовыми числами: `900`.
:::

:::deep Функция видит внешние переменные
Функция может читать переменные, объявленные снаружи. Это удобно, но делает её поведение зависимым от чужого состояния: результат меняется, хотя аргументы те же. Помощники для тестов лучше писать так, чтобы всё нужное приходило через параметры, а результат — через `return`.
:::

:::tech Объявление и функциональное выражение
`function name() {}` — объявление; его можно вызвать даже выше по тексту файла. `const name = function () {}` и `const name = () => {}` — выражения, присвоенные переменной; их можно вызвать только после этой строки. В тестах чаще встречаются стрелочные функции — о них следующий урок.
:::

:::interview
**Вопрос:** «Что такое чистая функция и почему её проще тестировать?» **Ответ по сути:** чистая функция зависит только от аргументов и не меняет ничего снаружи; для одинаковых аргументов результат всегда одинаков. Её тестируют простыми парами «вход → ожидаемый выход», без подготовки окружения.
:::
