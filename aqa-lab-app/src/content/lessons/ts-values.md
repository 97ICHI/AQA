:::why
Тест постоянно что-то запоминает: адрес страницы, название товара, ожидаемую сумму, ответ сервера. Для этого нужны переменные. Если понимать, чем `const` отличается от `let`, легко читать чужие тесты и не путаться, где значение меняется, а где нет.
:::

## Значение и переменная

**Значение** — это сами данные: число `390`, строка `'Блокнот A5'`, логическое `true`. **[[js-variable|Переменная]]** — имя, под которым значение сохранено, чтобы использовать его дальше.

```ts tests/cart.spec.ts
const productTitle = 'Блокнот A5';
const price = 390;
const qty = 2;
const expectedTotal = price * qty;   // 780

console.log(productTitle, expectedTotal);
```

Читается так: «создать переменную `productTitle` и положить в неё строку `'Блокнот A5'`». Знак `=` здесь — не «равно», а «присвоить»: значение справа сохраняется под именем слева. Справа может стоять выражение, например `price * qty`: сначала оно вычисляется, потом результат сохраняется.

## const и let

Переменную объявляют одним из двух слов:

- `const` — значение задаётся один раз и больше не переприсваивается. Большинство переменных в тестах — `const`.
- `let` — значение можно заменить позже. Нужен, когда что-то накапливается или меняется по ходу.

```ts tests/data/cart.ts
let itemsInCart = 0;
itemsInCart = itemsInCart + 1;   // добавили блокнот
itemsInCart = itemsInCart + 1;   // и ещё один
// itemsInCart теперь 2
```

Если объявить `const` и попытаться присвоить новое значение, TypeScript сообщит об ошибке ещё до запуска. Правило по умолчанию: пишите `const`, а `let` — только когда переприсваивание действительно нужно.

Старое слово `var` встречается в старом коде и статьях. В новом коде его не используют: у него неочевидные правила видимости.

## const не замораживает объект

Объект — это набор именованных значений в фигурных скобках (подробно — в уроке про массивы и объекты). Здесь важно одно: `const` запрещает **переприсвоить переменную**, но не запрещает **менять содержимое** объекта, на который она указывает.

```ts tests/data/cart.ts
const cart = { count: 0, total: 0 };
cart.count = 2;          // можно: меняем содержимое
cart.total = 780;        // можно
// cart = { count: 0, total: 0 };  // нельзя: это переприсваивание
```

`const` — это «имя всегда указывает на один и тот же объект», а не «объект неизменяем». Поэтому общий объект с тестовыми данными, объявленный через `const`, может быть случайно испорчен одним тестом и сломать другой.

Запустите код. Затем раскомментируйте последнюю строку (уберите `//`) и запустите снова: появится ошибка типа.
:::

`itemsInCart` объявлена через `let`, поэтому её можно увеличивать: она стала `2`. Объект `cart` объявлен через `const`, но его поля изменились — это разрешено, сама переменная по-прежнему указывает на тот же объект.

Если раскомментировать `deliveryPrice = 0`, компилятор выдаёт ошибку `TS2588: Cannot assign to 'deliveryPrice' because it is a constant` — «нельзя присвоить: это константа». Это ошибка типа, найденная до запуска.
:::

## Имена переменных

Имя должно объяснять, что внутри: `expectedTotal`, а не `x`; `productTitle`, а не `s`. В JavaScript принято писать имена в стиле camelCase: первое слово с маленькой буквы, следующие — с большой. Регистр важен: `price` и `Price` — разные переменные.

:::mistake Всё через let «на всякий случай»
`let` там, где значение не меняется, лишает читателя подсказки. Увидев `const`, сразу понятно: дальше это значение не подменят. Увидев `let`, приходится искать, где оно меняется.
:::

:::deep Как всё-таки сделать объект неизменяемым
`Object.freeze(obj)` запрещает менять поля объекта во время выполнения (только верхний уровень, вложенные объекты остаются изменяемыми). На уровне типов есть `readonly`-поля и `as const`. В тестах проще другое: не делить изменяемые объекты между тестами, а создавать свежие данные в каждом тесте.
:::

:::tech Видимость переменной
`const` и `let` видны внутри ближайших фигурных скобок `{ … }`, где объявлены, — в блоке `if`, цикле или функции. Переменная из одного теста не видна в другом. Две переменные с одним именем в одном блоке объявить нельзя.
:::

:::interview
**Вопрос:** «Чем `const` отличается от `let`, и можно ли изменить объект, объявленный через `const`?» **Ответ по сути:** `const` запрещает переприсваивание переменной, `let` разрешает. Содержимое объекта или массива, объявленного через `const`, менять можно: `const` фиксирует ссылку, а не данные.
:::
