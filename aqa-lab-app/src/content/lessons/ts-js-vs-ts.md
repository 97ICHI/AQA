:::why
Тесты Playwright пишут на TypeScript. Чтобы читать и писать их, не нужно становиться разработчиком, но нужно понимать, что происходит с кодом: какая часть *выполняется*, а какая *проверяется заранее*. Тогда сообщения об ошибках перестают быть загадкой.
:::

## Программа — это инструкции по порядку

Программа — текст, который компьютер выполняет строка за строкой, сверху вниз. Тест из первого урока — тоже программа: открыть страницу, нажать кнопку, сравнить счётчик с ожидаемым.

Язык, на котором выполняются такие программы в браузере и в Node.js, — [[javascript|JavaScript]]. Он очень снисходителен: многие сомнительные вещи он молча «как-то» выполняет. Например, если сложить строку `'390'` и число `100`, JavaScript не сообщит об ошибке, а склеит их в строку `'390100'`.

## Что добавляет TypeScript

[[typescript|TypeScript]] — это JavaScript плюс **типы**: пометки о том, какие значения где допустимы. Запись `const price: number = 390` означает «в `price` лежит число». Такая пометка называется [[type-annotation|аннотацией типа]].

Ключевая идея: типы проверяет отдельная программа — компилятор TypeScript — **до запуска**. При выполнении типов уже нет: TypeScript превращается в обычный JavaScript, и выполняется именно он.

Отсюда два вида ошибок:

- [[type-error|Ошибка типа]] — компилятор нашёл несоответствие, глядя на текст программы. Код ещё не запускался.
- [[runtime-error|Ошибка выполнения]] — программа запустилась и сломалась (или, что хуже, тихо посчитала неправильно).

```ts tests/data/cart.ts
const priceFromForm = '390';  // строка: так приходят значения из полей ввода
const delivery = 100;
const total = priceFromForm + delivery;
console.log(total);           // '390100' — не 490
```

В этом коде нет ни одной ошибки типа: сложить строку и число в JavaScript разрешено. Но результат неверный. Если же явно сказать, что ожидается число, компилятор заметит проблему сразу:

```ts tests/data/cart.ts
const price: number = '390';
// error TS2322: Type 'string' is not assignable to type 'number'.
```

:::try Посмотрите на обе ошибки
Нажмите «Запустить». Песочница сначала проверяет типы, затем всё равно выполняет получившийся JavaScript — так видно и ошибку типа, и то, что получается при запуске. Затем исправьте `'390'` на `390` (без кавычек) и запустите снова.
:::

```widget
{"type": "playground", "lang": "ts", "title": "Строка вместо числа", "code": "const priceFromForm = '390';\nconst delivery = 100;\n\nconst total = priceFromForm + delivery;\nconsole.log('Итого:', total);\n\nconst price: number = priceFromForm;\nconsole.log('Цена со скидкой 10%:', price * 0.9);\n"}
```

:::happened
В выводе две разные вещи.

Сначала строка `error TS2322` — это **ошибка типа**: компилятор прочитал текст программы и увидел, что в переменную для числа кладут строку. Номер строки и столбца указывает на место.

Затем идёт вывод выполнения: `Итого: 390100`. Это не ошибка с точки зрения JavaScript — он просто склеил строки. Строка `Цена со скидкой 10%: 351` тоже напечаталась: при умножении JavaScript сам превратил строку в число. Код «работает», но первый результат неверный, и узнать об этом можно только по смыслу.

В настоящем проекте код с ошибкой типа не должен попадать в общий репозиторий: его останавливает отдельная проверка типов (урок [[tsc-noemit|про tsc --noEmit]]).
:::

## Почему для тестов это важно

Тесты работают с данными: ценами, количествами, ответами сервера. Опечатка в имени поля или строка вместо числа в тестовых данных — частая причина ложных падений и, хуже, ложных прохождений. TypeScript ловит такие ошибки в редакторе, пока вы печатаете, а не через десять минут прогона.

Но у типов есть граница: они проверяют **ваш код**, а не то, что реально пришлёт сервер. Это разберём в уроке [[unknown-type|про unknown]].

:::mistake Убрать аннотацию, чтобы ошибка исчезла
Если удалить `: number`, ошибка типа пропадёт, но строка останется строкой и поедет дальше по тесту. Ошибка типа — подсказка, что данные не те, а не помеха, которую надо заглушить.
:::

:::deep Как именно TypeScript превращается в JavaScript
Компилятор делает две независимые вещи: **проверяет типы** и **стирает их**, выдавая JavaScript. Стирание не зависит от проверки: даже код с ошибками типов обычно превращается в рабочий JavaScript. Поэтому песочница смогла выполнить пример. Многие инструменты, включая Playwright Test, только стирают типы и сразу запускают тесты, не проверяя их. Проверку запускают отдельно.
:::

:::tech Где выполняется код в этом приложении
Код песочницы проверяется компилятором TypeScript 5.9 в режиме `strict` и выполняется в Web Worker — отдельном потоке браузера без доступа к странице. Это не Node.js: нет файлов и сети, зато есть `console.log`, таймеры и учебные функции `sleep` и `fakeFetchOrder`.
:::

:::interview
**Вопрос:** «Чем TypeScript отличается от JavaScript?» **Ответ по сути:** TypeScript добавляет статические типы, которые проверяются компилятором до запуска; при выполнении типов нет — выполняется JavaScript. Типы ловят ошибки в коде и тестовых данных раньше, но не проверяют данные, пришедшие во время выполнения (например, JSON от сервера).
:::
