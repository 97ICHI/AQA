:::why
Одна и та же проверка нужна во многих тестах: посчитать сумму заказа, найти пользователя, сравнить ответ с ожиданием. Если копировать код, исправление придётся вносить в десяти местах — и в одном обязательно забудут. Функция даёт проверке имя и одно место, где она живёт.
:::

## Объявление и вызов

Функция объявляется словом `def`, тело — с отступом. `return` возвращает результат и завершает функцию:

```py tests/helpers.py
def line_total(item):
    """Стоимость позиции: цена × количество."""
    return item["price"] * item["qty"]


print(line_total({"price": 390, "qty": 2}))   # 780
```

Строка в тройных кавычках сразу после `def` — docstring, описание функции. Его показывают редактор и `help(line_total)`.

Если `return` нет или он пустой, функция возвращает `None`. Это частая ошибка: функция что-то посчитала и напечатала через `print`, но вызывающий код получил `None`. Печать — для человека, `return` — для кода.

## Параметры

Параметры бывают обязательными и с **значением по умолчанию**:

```py tests/helpers.py
def order_total(items, discount_percent=0):
    total = sum(line_total(i) for i in items)
    return round(total * (100 - discount_percent) / 100, 2)


order_total(items)                        # без скидки
order_total(items, 10)                    # позиционно
order_total(items, discount_percent=10)   # по имени — читается лучше
```

Параметры по умолчанию идут после обязательных. Аргумент по имени (`discount_percent=10`) делает вызов самодокументируемым: через полгода понятно, что такое `10`.

:::mistake Изменяемое значение по умолчанию
`def add_item(item, items=[]):` — ловушка. Список по умолчанию создаётся **один раз** при объявлении функции и общий для всех вызовов: второй вызов увидит элемент, добавленный первым. Правильно: `def add_item(item, items=None):` и внутри `if items is None: items = []`.
:::

## Функция-проверка

В тестах полезны два вида функций. **Функция-расчёт** возвращает значение, а тест сравнивает его с ожиданием. **Функция-проверка** сама проверяет и падает с понятным сообщением:

```py tests/checks.py
def assert_order_consistent(order):
    expected = sum(line_total(i) for i in order["items"])
    assert order["total"] == expected, (
        f"заказ {order['id']}: total={order['total']}, а сумма позиций {expected}"
    )
```

Сообщение после запятой в `assert` — то, что увидит человек при падении. Хорошее сообщение содержит идентификатор объекта, ожидание и факт.

Функция может вернуть несколько значений — на самом деле это кортеж, который удобно «распаковать»: `good, bad = split_items(items)`.

:::deep Область видимости
Переменные, созданные внутри функции, — локальные: снаружи их не видно, и они исчезают после возврата. Функция может читать глобальные переменные модуля, но присваивание внутри функции создаёт локальную. Вспомогательные функции для тестов лучше делать «чистыми»: всё нужное — через параметры, результат — через `return`, без чтения и изменения глобального состояния. Такие функции легко тестировать и безопасно вызывать из параллельных тестов.
:::

:::tech Аннотации типов
Сигнатуру можно аннотировать: `def order_total(items: list[dict], discount_percent: float = 0) -> float:`. Python аннотации не проверяет, но редактор подсказывает типы и находит опечатки, а mypy/pyright проверяют их в CI. В тестовых фреймворках аннотации помогают понять, что принимает fixture или вспомогательный клиент.
:::

:::interview
**Вопрос:** «Почему нельзя использовать список как значение параметра по умолчанию?» **Ответ по сути:** значение по умолчанию вычисляется один раз при определении функции, и изменяемый объект становится общим для всех вызовов — данные «протекают» между вызовами. Используют `None` и создают список внутри функции.
:::
