:::why
Тест постоянно переводит данные из одного вида в другой: цену со страницы «4 990 ₽» — в число, сумму из базы `'5770.00'` — в число, число — обратно в текст для сравнения с интерфейсом. Ошибки здесь мелкие, но коварные: неразрывный пробел, лишний ноль после запятой, `0.1 + 0.2`.
:::

## Строки

Строка — неизменяемая последовательность символов. Методы строки возвращают **новую** строку, исходная не меняется:

| Метод | Пример | Результат |
|---|---|---|
| `strip()` | `"  390 ₽ ".strip()` | `"390 ₽"` |
| `replace(a, b)` | `"4 990".replace(" ", "")` | `"4990"` |
| `split(sep)` | `"a@b.test".split("@")` | `["a", "b.test"]` |
| `lower()`, `upper()` | `"PAID".lower()` | `"paid"` |
| `startswith(s)` | `"PULSE-01".startswith("PULSE")` | `True` |
| `in` | `"Pulse" in "Наушники Pulse"` | `True` |

`len("Блокнот")` — длина (7). Отдельный символ — по индексу с нуля: `"Блокнот"[0]` — `"Б"`, `[-1]` — последний. Срез `s[1:4]` — символы с 1-го по 3-й.

### f-строки и форматирование

[[f-string|f-строка]] подставляет значения в текст. После двоеточия внутри скобок задаётся формат:

```py tests/format.py
total = 4990
price = 390.5
print(f"Итого: {total} ₽")             # Итого: 4990 ₽
print(f"{price:.2f}")                   # 390.50 — два знака после точки
print(f"{1234567:,}")                   # 1,234,567 — разделитель тысяч
print(f"{1234567:,}".replace(",", " ")) # 1 234 567
```

## Числа

`int` — целые числа произвольной длины. `float` — дробные, с ограниченной точностью. Деление `/` всегда даёт `float` (`10 / 2` — `5.0`), целочисленное `//` — целую часть (`7 // 2` — `3`), `%` — остаток.

Преобразования типов делаются явно: `int("390")` — `390`, `float("5770.00")` — `5770.0`, `str(390)` — `"390"`. Если строка не похожа на число, `int()` бросает `ValueError` — об обработке ошибок будет отдельный урок.

### Почему 0.1 + 0.2 != 0.3

`float` хранит числа в двоичном виде, и многие десятичные дроби в нём представлены приближённо. Это не особенность Python — так устроены числа с плавающей точкой во всех языках ([[float-precision|точность float]]):

```py tests/money.py
print(0.1 + 0.2)            # 0.30000000000000004
print(0.1 + 0.2 == 0.3)     # False

from decimal import Decimal
print(Decimal("0.1") + Decimal("0.2") == Decimal("0.3"))  # True
```

Для денег в тестах есть три надёжных пути: считать в копейках целыми числами; использовать `decimal.Decimal`, созданный **из строки**; сравнивать `float` с допуском — `math.isclose(a, b)` или `pytest.approx` в тестах.

:::deep round и банковское округление
`round(2.5)` в Python — `2`, а `round(3.5)` — `4`: используется округление к чётному (banker's rounding), чтобы ошибки округления не накапливались в одну сторону. Кроме того, `round(2.675, 2)` даёт `2.67`, потому что 2.675 в `float` хранится как 2.67499999…. Если правила округления важны (деньги, налоги), используйте `Decimal` с явным режимом: `Decimal("2.675").quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`.
:::

:::tech Кодировки
Строки Python 3 — Unicode, кириллица и `₽` работают без дополнительных настроек. Кодировка появляется на границе: при чтении и записи файлов и сети. Всегда указывайте её явно: `open(path, encoding="utf-8")`. Байты (`bytes`) превращаются в строку через `.decode("utf-8")`, строка в байты — через `.encode("utf-8")`.
:::

**Вопрос:** «Почему `0.1 + 0.2 != 0.3` и как сравнивать дробные числа в тестах?» **Ответ по сути:** `float` хранит двоичное приближение десятичной дроби, ошибки округления накапливаются. В тестах сравнивают с допуском (`pytest.approx`, `math.isclose`), а деньги считают в целых копейках или в `Decimal`, созданном из строки.
