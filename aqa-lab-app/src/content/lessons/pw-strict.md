:::why
Что должен делать тест, если «кнопку В корзину у наушников Pulse» подходят две кнопки? Угадать — значит однажды молча нажать не ту. Playwright в такой ситуации останавливается с ошибкой. В этом уроке вы научитесь читать эту ошибку и исправлять локатор так, чтобы он находил ровно то, что имел в виду автор, — и продолжал находить, когда в каталоге появятся похожие товары.
:::

## Строгость локаторов

Действия (`click`, `fill`, `check` и другие) и большинство проверок работают с **одним** элементом. Если локатор в момент действия нашёл больше одного, Playwright не выбирает за вас: действие падает с ошибкой `strict mode violation`. Это правило называется [[strict-mode|строгим режимом]].

В каталоге магазина есть «Наушники Pulse» и «Наушники Pulse Pro». Локатор по подстроке находит обе карточки:

```ts tests/strict.spec.ts
const card = page.getByRole('listitem').filter({ hasText: 'Наушники Pulse' });
await card.getByRole('button', { name: 'В корзину' }).click();   // две кнопки
```

:::

## Плохое исправление: first()

Самый быстрый способ «починить» — добавить `.first()`:

```ts
await card.first().getByRole('button', { name: 'В корзину' }).click();
```

Ошибка исчезнет, но тест теперь зависит от **порядка** карточек. Сегодня «Наушники Pulse» стоят первыми. Если каталог отсортируют по цене или новый товар окажется выше, тест молча положит в корзину другой товар — и, возможно, даже пройдёт, если проверка слабая. `first()`, `last()` и `nth()` уместны, только когда порядок — часть требования: «первый результат поиска — самый релевантный».

## Хорошие исправления

Сначала сформулируйте, *что именно* вы ищете, словами пользователя, а затем переведите это в локатор.

**1. Точное имя заголовка карточки.** «Карточка, у которой заголовок — ровно „Наушники Pulse Pro“»:

```ts
const card = page.getByRole('listitem').filter({
  has: page.getByRole('heading', { name: 'Наушники Pulse Pro', exact: true }),
});
```

`exact: true` отсекает «Наушники Pulse Pro Max», а `has` ищет заголовок внутри каждой карточки.

**2. Ограничить область поиска.** Если на странице два списка (например, «Рекомендуем» и «Товары»), сначала найдите нужный: `page.getByRole('list', { name: 'Товары' }).getByRole('listitem')…`.

**3. Test id на карточке**, если разработчики его добавили: `page.getByTestId('product-PULSE-02')`.

```widget
{"type":"locator-lab","task":"Найдите кнопку «В корзину» только у «Наушники Pulse» (без Pro). Попробуйте filter({ hasText: 'Наушники Pulse' }), посмотрите на число совпадений, затем сравните с first() и прочитайте подсказку модели."}
```

Учебная модель понимает только `filter({ hasText })`. На настоящей странице для этой задачи берите `has` с точным заголовком, как в примере выше.

## Когда проверка не строгая

Строгость касается действий и проверок одного элемента (`toHaveText`, `toBeVisible`…). Некоторые проверки специально работают со списком: `toHaveCount(n)` считает элементы, а `toHaveText([...])` с массивом сравнивает тексты всех найденных элементов по порядку:

```ts
await page.getByRole('searchbox', { name: 'Поиск товара' }).fill('Pulse');
await page.getByRole('button', { name: 'Найти' }).click();
await expect(page.getByRole('listitem').getByRole('heading'))
  .toHaveText(['Наушники Pulse', 'Наушники Pulse Pro']);
```

## Задание

В магазине-варианте «похожие названия» появляются «Наушники Pulse Pro Max» и «Чехол для наушников Pulse». Тест должен выдержать эти новые данные.

```widget
{"type":"exercise","id":"m5-strict-pulse-pro"}
```

:::mistake
**Чинить strict violation через `.first()` «чтобы заработало».** Тест перестаёт падать, но теперь может проверять не тот элемент. Вопрос, который нужно задать: «Какой из найденных элементов я на самом деле имел в виду и чем он отличается для пользователя?» Ответ и есть уточнение локатора.
:::

:::deep Зачем строгость, если можно было бы брать первый
В Selenium-подобных инструментах `findElement` возвращает первый найденный элемент. Это источник тихих ошибок: тест кликает не туда и падает тремя шагами позже с непонятной причиной — или не падает вовсе. Строгий режим превращает неоднозначность в ошибку ровно в том месте, где она возникла, и с перечнем кандидатов. Это пример принципа «падать рано и громко».
:::

:::tech Что считается одним элементом
Строгость проверяется в момент действия, а не при создании локатора. Локатор, который сейчас находит два элемента, может через секунду найти один (например, второй исчез после фильтрации) — тогда действие пройдёт. Методы чтения списков (`count()`, `all()`, `allTextContents()`) строгостью не ограничены, но читают состояние один раз, без ожидания; для проверок предпочтительнее `toHaveCount` и `toHaveText([...])`.
:::

:::interview
**Вопрос:** «Тест упал со strict mode violation. Ваши действия?» **Ответ по сути:** прочитать список найденных элементов, понять, какой из них нужен и чем он отличается для пользователя (точное имя, контейнер, состояние), и уточнить локатор через `exact`, `has`, цепочку от контейнера или test id. `first()`/`nth()` — только если порядок является требованием.
:::
