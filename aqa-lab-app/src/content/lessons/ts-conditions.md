:::why
Тест — это сравнение: «получили то, что ожидали?». А логика магазина, которую тест проверяет, полна условий: бесплатная доставка от суммы, скидка для клуба, кнопка недоступна без товара. Чтобы понимать и то и другое, нужны сравнения и условия — и знание пары ловушек JavaScript.
:::

## Сравнения

Сравнение даёт логическое значение `true` или `false`:

| Запись | Смысл |
|---|---|
| `a === b` | равно (и значение, и тип) |
| `a !== b` | не равно |
| `a > b`, `a >= b` | больше, больше или равно |
| `a < b`, `a <= b` | меньше, меньше или равно |

Используйте [[strict-equality|строгое сравнение]] `===` и `!==`. В JavaScript есть ещё `==`, который перед сравнением *приводит типы*: `'390' == 390` даёт `true`. Для теста это опасно: строка вместо числа в ответе сервера — дефект, а `==` его скроет. `'390' === 390` честно даёт `false`.

## if и else

Условие выполняет код, только если выражение в скобках истинно:

```ts src/shop/delivery.ts
const total = 2500;
let delivery;
if (total >= 3000) {
  delivery = 0;
} else {
  delivery = 300;
}
// delivery === 300
```

Короткая запись для выбора одного из двух значений — тернарный оператор `условие ? еслиДа : еслиНет`: `const delivery = total >= 3000 ? 0 : 300;`.

## И, ИЛИ, НЕ

- `a && b` — «и»: истинно, только если истинны оба.
- `a || b` — «или»: истинно, если истинно хотя бы одно.
- `!a` — «не»: переворачивает значение.

```ts src/shop/delivery.ts
const isMember = true;
const freeDelivery = total >= 3000 || isMember;   // true: участнику клуба бесплатно
const canCheckout = itemsCount > 0 && !isBlocked;
```

## Truthy и falsy: откуда берутся сюрпризы

В условии может стоять не только `true`/`false`, но любое значение. JavaScript тогда сам решает, считать ли его «истинным». «Ложными» ([[truthy-falsy|falsy]]) считаются: `false`, `0`, `''` (пустая строка), `null`, `undefined` и `NaN`. Всё остальное — «истинное».

Отсюда ловушка. Часто пишут `значение || поУмолчанию`, чтобы подставить запасное значение. Но `||` подставит его и для `0`, и для пустой строки:

```ts src/shop/discount.ts
const savedDiscount = 0;                 // покупатель осознанно без скидки
const discount1 = savedDiscount || 5;    // 5 — ошибка!
const discount2 = savedDiscount ?? 5;    // 0 — верно
```

Оператор [[nullish-coalescing|??]] подставляет запасное значение только для `null` и `undefined`. Для «значения по умолчанию» почти всегда нужен именно он.

Запустите код и сравните строки вывода. Затем поменяйте `savedDiscount` на `undefined` и посмотрите, когда `||` и `??` дают одинаковый результат.
:::

```widget

```

:::happened
`'390' === 390` даёт `false`: строка и число не равны, и это правильно. Поэтому `priceFromApi` здесь объявлена с типом `unknown` — «тип неизвестен». Если бы TypeScript знал, что там строка, он бы прямо сообщил: сравнение строки с числом всегда ложно. Тип `unknown` подробно — в отдельном уроке.

Сумма ровно 3000 даёт бесплатную доставку через `>=` и платную через `>`. Разница в одном символе — классический дефект на границе, и тест должен проверять именно граничное значение.

`0 || 5` дало `5`, а `0 ?? 5` — `0`. Пустой промокод `''` в `if` ведёт себя как `false`.
:::

:::mistake `if (count)` для проверки «число передано»
Если `count` может быть `0`, `if (count)` пропустит этот случай. Проверяйте то, что имеете в виду: `count !== undefined`, `count > 0`.
:::

:::deep Как работает `==`
`==` применяет правила приведения: строка превращается в число, `null == undefined` даёт `true`, `0 == ''` — `true`, `'0' == false` — `true`. Эти правила трудно держать в голове, поэтому во всех стандартах кода для тестов используют только `===`. Единственное распространённое исключение — `x == null`, что проверяет сразу и `null`, и `undefined`; но и его лучше писать явно.
:::

:::tech Короткое вычисление
`&&` и `||` возвращают не обязательно `true`/`false`, а одно из исходных значений: `a || b` возвращает `a`, если оно truthy, иначе `b`. Правая часть вычисляется, только если нужна: в `user && user.name` обращение к `name` не произойдёт, если `user` — `null`. Для этого есть и короткая запись `user?.name`.
:::

:::interview
**Вопрос:** «Чем `??` отличается от `||`?» **Ответ по сути:** `||` заменяет любое falsy-значение (`0`, `''`, `false`, `null`, `undefined`, `NaN`), а `??` — только `null` и `undefined`. Для значений по умолчанию, где `0` или пустая строка допустимы, нужен `??`.
:::
