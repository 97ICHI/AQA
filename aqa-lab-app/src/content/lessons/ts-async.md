:::why
Почти всё, что делает автотест, занимает время: открыть страницу, дождаться ответа сервера, найти кнопку. Код при этом не стоит на месте — если явно не сказать «подожди», он идёт дальше. Забытый `await` — одна из самых частых причин тестов, которые то проходят, то падают, или проходят, ничего не проверив.
:::

## Promise: результат, который будет позже

Когда операция занимает время, функция не может сразу вернуть результат. Вместо него она возвращает [[promise|Promise]] — «обещание результата». У него три состояния:

- **pending** — операция ещё идёт;
- **fulfilled** — завершилась успешно, есть значение;
- **rejected** — завершилась ошибкой.

В тренажёре есть две учебные асинхронные функции: `sleep(ms)` — Promise, который выполнится через `ms` миллисекунд, и `fakeFetchOrder(id)` — «запрос к API», отвечающий через 50 мс. В Playwright асинхронны почти все методы: `page.goto`, `locator.click`, `expect(locator).toHaveText`.

## async и await

[[async-await|await]] перед Promise означает: «остановись здесь, пока результат не будет готов, и дай мне значение». Использовать `await` можно внутри функции, помеченной `async`:

```ts tests/api/order.spec.ts
async function loadOrderStatus(id: number): Promise<string> {
  const data = await fakeFetchOrder(id);    // ждём ответ
  return (data as { status: string }).status;
}
```

Функция с `async` **всегда** возвращает Promise: её результат тоже нужно дожидаться через `await`. Поэтому тело теста Playwright — `async`-функция, и `await` стоит перед каждым действием и проверкой.

## Забытый await

Если `await` забыть, вызов запускает операцию и сразу возвращает Promise в состоянии pending, а код идёт дальше. Такой Promise, которого никто не ждёт, называют [[floating-promise|«висящим»]]. TypeScript это ошибкой **не** считает: вызвать функцию и не использовать результат разрешено.

```ts tests/cart.spec.ts
test('товар в корзине', async ({ page }) => {
  await page.goto('/');
  page.getByRole('button', { name: 'В корзину' }).first().click();   // ← нет await
  await expect(page.getByTestId('cart-count')).toHaveText('1');
});
```

Здесь клик запущен, но тест не ждёт его завершения. Иногда проверка успевает — тест проходит; иногда нет — падает. Хуже, если `await` забыт перед самой проверкой: тест может закончиться раньше, чем проверка выполнится, — и пройти, ничего не проверив.

Запустите код. Функция `saveOrder` «пишет в базу» 100 мс. Сравните, что видит код без `await` и с ним.
:::

:::

## Ошибки в асинхронном коде

Если асинхронная операция падает, Promise переходит в состояние rejected. С `await` такая ошибка ведёт себя как обычная: её можно поймать конструкцией `try { … } catch (e) { … }`, а в тесте она роняет тест с понятным сообщением. Без `await` ошибку не поймает никто: `try` давно закончился, когда Promise отклонился.

```widget
{"type": "playground", "lang": "ts", "title": "Ошибка без await и с await", "code": "async function pay(orderId: number): Promise<string> {\n  await sleep(50);\n  if (orderId === 42) throw new Error(`Оплата заказа №${orderId} отклонена`);\n  return 'ok';\n}\n\ntry {\n  pay(42);                            // без await\n  console.log('платёж «прошёл»?');\n} catch (e) {\n  console.log('сюда не попадём');\n}\n\ntry {\n  await pay(42);\n} catch (e) {\n  console.log('поймали:', (e as Error).message);\n}\n"}
```

:::happened
Первый `try` ничего не поймал: код напечатал «платёж прошёл?», хотя платёж отклонён. Ошибка всплыла в самом конце как `UnhandledPromiseRejection` — «Promise отклонён, и ошибку никто не обработал». Второй вызов с `await` поймал ошибку там, где её ждали.
:::

:::mistake Лечить гонку задержкой
`await sleep(500)` или `page.waitForTimeout(500)` «чинит» забытый `await` только на вашей машине и сегодня. Медленнее сервер — и тест снова падает; быстрее — и вы зря ждёте. Правильное исправление — дождаться именно той операции, результат которой нужен.
:::

:::deep Как это устроено: event loop
JavaScript выполняет код в одном потоке. `await` не блокирует поток, а приостанавливает функцию и возвращает управление [[event-loop|циклу событий]]; когда Promise выполнится, продолжение функции ставится в очередь. Поэтому, пока одна функция «ждёт», выполняется другой код, — в том числе код после вызова без `await`.
:::

:::tech then и catch
До `async/await` с Promise работали через методы: `fakeFetchOrder(1).then((data) => …).catch((e) => …)`. Это тот же механизм; `await` — более удобная запись. Вернуть Promise из функции (`return saveOrder(sku)`) — тоже способ дождаться: вызывающий код получит этот Promise и сможет его ждать.
:::

:::interview
**Вопрос:** «Что будет, если забыть `await` перед действием в тесте Playwright?» **Ответ по сути:** действие запустится, но тест не дождётся его и пойдёт дальше; следующий шаг может выполниться раньше, ошибка действия останется необработанной, а проверка без `await` может вообще не выполниться до конца теста. Результат — нестабильный или ложно проходящий тест. Ловится линтером (`no-floating-promises`) и ревью; TypeScript такой код пропускает.
:::
