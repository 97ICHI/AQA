:::why
Неожиданный факт: Playwright Test запускает тесты на TypeScript, но **не проверяет типы**. Тест с ошибкой типа запустится и, возможно, даже пройдёт. Вся польза типов из прошлых уроков появляется, только если проверку типов запускать отдельно — локально и в CI. Разберём, как это настроить.
:::

## Что делает Playwright с файлом .ts

Перед запуском Playwright Test превращает TypeScript в JavaScript: просто **стирает типы**. Проверку типов он не выполняет — так быстрее, и об этом прямо сказано в документации Playwright. Значит, ошибка типа никак не остановит прогон: тест упадёт (или не упадёт) только во время выполнения.

Проверку типов выполняет компилятор TypeScript — программа `tsc`. Команда [[tsc-noemit|tsc --noEmit]] проверяет весь проект и ничего не записывает на диск (`noEmit` — «не выпускать файлы»). Если есть ошибки, она печатает их и завершается с ненулевым кодом — именно это нужно CI, чтобы остановить pipeline.

## tsconfig.json

Настройки компилятора хранятся в [[tsconfig|tsconfig.json]] в корне проекта. Для тестового проекта Playwright достаточно небольшого файла:

```json tsconfig.json
{
  "compilerOptions": {
    "target": "ES2022",
    "module": "ESNext",
    "moduleResolution": "Bundler",
    "strict": true,
    "noEmit": true,
    "skipLibCheck": true,
    "types": ["node"]
  },
  "include": ["tests", "playwright.config.ts"]
}
```

- `strict` — включает строгие проверки. Без него TypeScript пропускает многие ошибки, ради которых его и используют.
- `noEmit` — `tsc` только проверяет; запускает тесты Playwright.
- `include` — какие файлы проверять.
- `types: ["node"]` — типы Node.js (нужен пакет `@types/node`), чтобы `process.env` не было ошибкой.

## Что включает strict

Режим [[ts-strict|strict]] — это набор флагов. Два самых заметных:

- **`noImplicitAny`** — параметр без типа становится ошибкой, а не молчаливым `any`.
- **`strictNullChecks`** — `null` и `undefined` перестают «подходить» к любому типу. `products.find(…)` возвращает `Product | undefined`, и обращение к `.price` без проверки — ошибка типа.

Без `strict` оба примера ниже компилируются без единого замечания, а падают при выполнении.

## Проверка как отдельный шаг

В package.json проверку типов оформляют скриптом и запускают перед тестами:

```json package.json
{
  "scripts": {
    "typecheck": "tsc --noEmit",
    "test": "playwright test"
  }
}
```

```bash
npm run typecheck && npm test
```

`&&` означает «вторую команду — только если первая успешна». В CI это обычно два отдельных шага: сначала проверка типов (несколько секунд), потом тесты (минуты). Ошибка в коде тестов обнаруживается сразу, а не после долгого прогона.

:::try Ошибки типа и ошибка выполнения
Песочница ведёт себя как Playwright: сначала проверяет типы (как `tsc --noEmit`), но **всё равно** выполняет код. Запустите и сравните, что нашёл компилятор и что произошло при выполнении.
:::

```widget
{"type": "playground", "lang": "ts", "title": "Код, который strict не пропустил бы", "code": "const catalog = [\n  { title: 'Блокнот A5', price: 390 },\n  { title: 'Ручка', price: 120 },\n];\n\nfunction priceOf(title) {\n  return catalog.find((p) => p.title === title).price;\n}\n\nconsole.log('блокнот:', priceOf('Блокнот A5'));\nconsole.log('глобус:', priceOf('Глобус'));\nconsole.log('сюда выполнение не дойдёт');\n"}
```

:::happened
Компилятор нашёл две ошибки: `TS7006` — параметр `title` неявно имеет тип `any` (это `noImplicitAny`), и `TS2532` — объект может быть `undefined` (это `strictNullChecks`: `find` может ничего не найти).

Код всё равно выполнился, как выполнился бы в Playwright. Для блокнота всё прошло, а для «Глобуса» — `TypeError: Cannot read properties of undefined (reading 'price')`, и последняя строка не напечаталась. Компилятор предупредил ровно об этом сценарии до запуска; `tsc --noEmit` в CI не пропустил бы такой код в общую ветку.
:::


:::mistake «Тесты зелёные — значит, с типами всё в порядке»
Playwright не проверяет типы, поэтому зелёный прогон ничего не говорит об ошибках типов. Если в проекте нет шага `tsc --noEmit`, ошибки копятся незаметно, пока одна из них не приведёт к ложно проходящему тесту.
:::

:::deep Почему Playwright не проверяет типы сам
Проверка типов требует анализа всего проекта сразу и занимает заметное время; стирание типов — быстрая операция над каждым файлом отдельно. Разделение позволяет запускать один тест мгновенно, а полную проверку — один раз на проект. Редактор (VS Code) при этом проверяет типы постоянно, пока вы печатаете, — но только в открытых файлах.
:::

:::tech Проверка типов в этом приложении
Песочницы и задания тренажёра компилируются TypeScript 5.9 с `strict: true`. В заданиях ошибка типа останавливает проверку: код не запускается, пока типы не исправлены, — как в проекте, где `tsc --noEmit` стоит перед тестами. В песочницах код выполняется даже с ошибками типов, чтобы было видно поведение во время выполнения.
:::

:::interview
**Вопрос:** «Проверяет ли Playwright типы при запуске тестов?» **Ответ по сути:** нет — он только преобразует TypeScript в JavaScript и запускает. Проверку типов выполняют отдельной командой `tsc --noEmit` с `strict` в tsconfig, локально и отдельным шагом CI перед прогоном тестов.
:::
