:::why
Каталог, корзина, список заказов — всё это массивы, и тесту часто нужно пройти по каждому элементу: посчитать сумму, найти нужный товар, убедиться, что у всех цена больше нуля. Сначала разберём обычный цикл — он показывает, что происходит. Затем методы массивов — ими такой код пишут короче.
:::

## Цикл for…of

[[js-loop|Цикл]] повторяет блок кода. `for…of` выполняет его по разу для каждого элемента массива:

```ts tests/data/cart.ts
const cart = [
  { title: 'Блокнот A5', price: 390, qty: 2 },
  { title: 'Ручка', price: 120, qty: 1 },
];

let total = 0;
for (const item of cart) {
  total = total + item.price * item.qty;   // можно короче: total += …
}
// total === 900
```

Читается так: «для каждого `item` из `cart` выполнить то, что в фигурных скобках». На первом проходе `item` — блокнот, на втором — ручка. Переменная `total` объявлена *до* цикла через `let`, чтобы накапливать сумму.

Встречается и классический цикл со счётчиком: `for (let i = 0; i < cart.length; i++) { … }`. Он нужен, когда важен номер элемента; в остальных случаях `for…of` проще и не даёт ошибиться с границей.

Внутри цикла можно использовать условие, а `break` прерывает цикл досрочно.

## Методы массивов: filter, map, find

Три задачи встречаются так часто, что для них есть готовые [[array-methods|методы массива]]:

| Метод | Что делает | Результат |
|---|---|---|
| `filter(условие)` | оставляет элементы, для которых условие истинно | новый массив (может быть пустым) |
| `map(преобразование)` | превращает каждый элемент во что-то другое | новый массив той же длины |
| `find(условие)` | ищет первый подходящий элемент | элемент или `undefined` |

```ts tests/data/catalog.ts
const products = [
  { title: 'Блокнот A5', price: 390, stock: 12 },
  { title: 'Наушники Pulse', price: 4990, stock: 0 },
  { title: 'Ручка', price: 120, stock: 40 },
];

const available = products.filter((p) => p.stock > 0);   // блокнот и ручка
const titles = products.map((p) => p.title);              // ['Блокнот A5', 'Наушники Pulse', 'Ручка']
const pulse = products.find((p) => p.title === 'Наушники Pulse');   // объект наушников
```

Запись `(p) => p.stock > 0` — это маленькая функция: «получить товар `p`, вернуть результат сравнения». Метод сам вызывает её для каждого элемента. Подробно такие функции разберём в уроке про стрелочные функции; пока читайте её как «для товара p — условие».

Методы можно соединять в цепочку: `products.filter((p) => p.stock > 0).map((p) => p.title)` — названия товаров в наличии. Исходный массив при этом не меняется.

Ещё два полезных метода для проверок: `some(условие)` — «есть ли хоть один», `every(условие)` — «все ли».

:::mistake Проверка по пустому списку
`products.every((p) => p.price > 0)` для **пустого** массива возвращает `true`. Если тест проверяет «у всех товаров есть цена», но каталог по ошибке пуст, проверка пройдёт. Добавляйте проверку, что список не пустой.
:::

:::deep forEach и reduce
`forEach(fn)` вызывает функцию для каждого элемента и ничего не возвращает — это аналог `for…of`. `reduce` сворачивает массив в одно значение: `cart.reduce((sum, i) => sum + i.price * i.qty, 0)`. Начальное значение `0` обязательно: без него `reduce` на пустом массиве бросает ошибку. С асинхронным кодом `forEach` работает не так, как ожидают, — это разберём в уроке про `Promise.all`.
:::

:::tech Методы, которые меняют массив
`push`, `pop`, `sort`, `reverse`, `splice` меняют исходный массив. `filter`, `map`, `slice`, `concat` возвращают новый. В тестах, где исходные данные общие, безопаснее работать с копией: `[...products].sort(…)`.
:::

:::interview
**Вопрос:** «Чем `find` отличается от `filter`?» **Ответ по сути:** `find` возвращает первый подходящий элемент или `undefined`; `filter` — новый массив всех подходящих (возможно, пустой). Для проверки «товар есть» после `find` проверяют на `undefined`, после `filter` — длину.
:::
