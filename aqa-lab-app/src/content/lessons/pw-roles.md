:::why
Пользователь не видит классов и id. Он видит «кнопку „В корзину“», «поле поиска», «ссылку „Корзина“». Если тест ищет элементы так же, он не ломается от смены вёрстки и заодно проверяет, что элемент понятен вспомогательным технологиям — экранным чтецам. В этом уроке вы научитесь описывать элемент через роль и доступное имя.
:::

## Роль и доступное имя

Браузер строит из HTML не только картинку, но и дерево доступности — описание страницы для экранных чтецов. У каждого элемента в нём есть:

- **[[aria-role|роль]]** — *что это*: `button`, `link`, `textbox`, `heading`, `listitem`, `checkbox`…
- **[[accessible-name|доступное имя]]** — *как называется*: текст кнопки, подпись поля, `alt` картинки.

Роль чаще всего берётся из тега (неявная роль), а иногда задаётся атрибутом `role`:

| HTML магазина | Роль | Доступное имя |
|---|---|---|
| `<button>В корзину</button>` | `button` | «В корзину» — из текста |
| `<a href="/cart">Корзина (0)</a>` | `link` | «Корзина (0)» |
| `<h2>Кружка</h2>` | `heading` | «Кружка» |
| `<label for="q">Поиск товара</label><input id="q" type="search">` | `searchbox` | «Поиск товара» — из `label` |
| `<input type="email">` с подписью «Email» | `textbox` | «Email» |
| `<li>` внутри `<ul aria-label="Товары">` | `listitem` | — |
| `<p role="status">` | `status` | — |
| `<form role="search">` | `search` | — |

Обратите внимание на две особенности. Поле `type="search"` имеет роль **`searchbox`**, а не `textbox`. А у поля `type="password"` роли нет совсем — его ищут по подписи через `getByLabel('Пароль')`.

## getByRole

```ts tests/roles.spec.ts
await page.getByRole('searchbox', { name: 'Поиск товара' }).fill('Кружка');
await page.getByRole('button', { name: 'Найти' }).click();
await expect(page.getByRole('heading', { name: 'Кружка' })).toBeVisible();
await page.getByRole('link', { name: /Корзина/ }).click();
await expect(page.getByRole('row', { name: /Кружка/ })).toBeVisible();
```

Как сравнивается `name`:

- **строка** — без учёта регистра и по подстроке: `{ name: 'корзин' }` найдёт и «В корзину», и «Корзина (0)»;
- **строка с `exact: true`** — полное совпадение с учётом регистра;
- **регулярное выражение** — `/Корзина/` удобно, когда часть имени меняется (счётчик в ссылке «Корзина (2)»).

Кроме `name`, у `getByRole` есть уточнения по состоянию: `checked`, `disabled`, `expanded`, `pressed`, `selected` и `level` для заголовков (`{ level: 1 }` — только `h1`).

Это учебная модель страницы магазина: роль и имя в ней вычисляются по упрощённым правилам. Введите локатор и посмотрите, сколько элементов он находит. Попробуйте: `page.getByRole('button', { name: 'В корзину' })` — почему совпадений три, хотя на одной кнопке написано «+»? Затем найдите только кнопку кабеля и поле поиска.
:::

```widget
{"type":"locator-lab","task":"Найдите ровно один элемент: кнопку добавления кабеля USB-C (на ней только «+»), затем поле поиска по его роли и подписи."}
```

:::happened
У кнопки с «+» есть атрибут `aria-label="Добавить кабель в корзину"`. Он **заменяет** текст кнопки в доступном имени, поэтому имя кнопки — «Добавить кабель в корзину», и подстрока «в корзину» в нём есть. Так `getByRole` и находит её третьей. Точный локатор: `page.getByRole('button', { name: 'Добавить кабель в корзину' })`. Поле поиска — `page.getByRole('searchbox', { name: 'Поиск товара' })`.
:::

## Что будет с неверной ролью

Если роль указана неверно, локатор ничего не найдёт. Действие будет ждать появления элемента до таймаута — и упадёт.

```widget
{"type":"playground","lang":"pw","title":"Неверная роль: textbox вместо searchbox","variant":"ok","code":"import { test, expect } from '@playwright/test';\n\ntest('поле поиска по роли textbox', async ({ page }) => {\n  await page.goto('/');\n  await page.getByRole('textbox', { name: 'Поиск товара' }).fill('Кружка', { timeout: 2000 });\n});\n","recorded":{"variant":"Исправный магазин","output":"✗ поле поиска по роли textbox (2257 мс)\nTimeoutError: locator.fill: Timeout 2000ms exceeded.\nCall log:\n  - waiting for getByRole('textbox', { name: 'Поиск товара' })\n"}}
```

:::happened
`fill` ждал элемент с ролью `textbox` и именем «Поиск товара» 2 секунды (такой таймаут задан в примере) и не дождался: у поля роль `searchbox`. Сообщение говорит, *что* искалось, — по нему видно, что ошибка в тесте, а не в магазине. Если вы не уверены в роли, откройте DevTools → вкладка Accessibility или используйте `npx playwright codegen`: генератор предлагает локаторы по ролям.
:::

## Задание

```widget
{"type":"exercise","id":"m5-roles-search-cart"}
```

:::mistake
**Искать по роли `generic` или по тексту там, где есть роль.** `page.getByText('В корзину').click()` сработает, пока на странице одна такая надпись, но не скажет ничего о том, что это кнопка. Если разработчик сделает «кнопку» из `<div>` без роли, тест на тексте пройдёт, а пользователь клавиатуры её не нажмёт. `getByRole('button', …)` такую проблему заметит.
:::

:::deep Как на самом деле вычисляется имя
Порядок источников имени задаёт спецификация W3C «Accessible Name and Description Computation». Упрощённо: `aria-labelledby` → `aria-label` → связанный `label` (для полей) → `alt` (для картинок) → текст содержимого (для кнопок, ссылок, заголовков) → `title`. Лаборатория в этом уроке реализует только часть правил, а Playwright — полный алгоритм. Поэтому на сложной разметке проверяйте локатор на настоящей странице.
:::

:::tech Скрытые элементы
По умолчанию `getByRole` пропускает элементы, скрытые от дерева доступности (`display: none`, `aria-hidden="true"`). Опция `includeHidden: true` включает их. Проверка `toHaveAccessibleName` в `expect` сравнивает доступное имя элемента — полезна, когда имя важно само по себе, например у кнопки-иконки.
:::

:::interview
**Вопрос:** «Почему `getByRole` предпочтительнее CSS-селектора?» **Ответ по сути:** роль и имя — это то, что видит и использует пользователь; они меняются редко и только вместе с поведением. Классы и структура меняются при любой переработке вёрстки. Заодно локатор по роли проверяет базовую доступность: элемент без роли или имени не найдётся.
:::
