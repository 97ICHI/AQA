:::why
Автотест — это программа, которая выполняет действия пользователя и **проверяет результат**. В этом уроке вы запустите настоящий тест учебного магазина, увидите, как он проходит, затем включите дефект и увидите, как тот же тест падает и что именно он сообщает.

## Учебный магазин

Во всех практических уроках используется один и тот же учебный магазин: каталог → поиск → корзина → вход → заказ. Он запускается на вашем компьютере вместе с [[aqa-runner|runner]] и хранит данные в памяти, поэтому каждый запуск начинается с чистого состояния. В магазин можно «подложить» дефект — например, сделать так, чтобы товар не добавлялся в корзину. Хороший тест такие дефекты замечает.

## Тест целиком

```ts tests/cart.spec.ts
import { test, expect } from '@playwright/test';

test('блокнот добавляется в корзину', async ({ page }) => {
  await page.goto('/');                                                   // 1. открыть каталог
  const card = page.getByRole('listitem').filter({ hasText: 'Блокнот A5' }); // 2. найти карточку
  await card.getByRole('button', { name: 'В корзину' }).click();          // 3. действие
  await expect(page.getByTestId('cart-count')).toHaveText('1');           // 4. проверка
});
```

Четыре части есть почти в любом UI-тесте:

1. **Подготовка** — `page.goto('/')` открывает страницу. Адрес `/` дополняется до полного с помощью `baseURL` из конфигурации.
2. **Поиск элемента** — [[locator|локатор]] описывает, *как найти* элемент: «элемент списка, в тексте которого есть „Блокнот A5“». Сам по себе локатор ничего не ищет — поиск происходит в момент действия или проверки.
3. **Действие** — `click()`. Перед кликом Playwright [[auto-waiting|ждёт]], пока кнопка появится, станет видимой и доступной.
4. **Проверка** — [[assertion|assertion]] `toHaveText('1')`. Она тоже ждёт: повторяет проверку, пока текст не станет `1` или не истечёт таймаут.

`await` стоит перед каждым действием и проверкой: это асинхронные операции, и без `await` тест пойдёт дальше, не дождавшись результата. Подробно — в уроке [[async-await|про async/await]].

## Тот же тест на магазине с дефектом

Теперь магазин сломан: кнопка «В корзину» отвечает, но товар не добавляется. Код теста тот же.


:::happened
Сообщение о падении отвечает на три вопроса:

- **что проверялось** — `Locator: getByTestId('cart-count')`;
- **что ожидалось и что получено** — `Expected: "1"`, `Received: "0"`;
- **сколько ждали** — `Timeout: 3000ms`, и в журнале видно, что элемент нашёлся 7 раз, но значение оставалось `0`.

Элемент на месте, кнопка нажалась, но счётчик не изменился. Значит, проблема в приложении, а не в тесте: это **дефект**. Как отличать дефект от ошибки в самом тесте — в следующем уроке.
:::

:::deep Почему проверка счётчика после каждого клика
Второй клик может произойти раньше, чем закончился первый запрос в корзину. Проверка `toHaveText('1')` между кликами гарантирует, что первое добавление завершилось, и делает тест независимым от скорости магазина. На варианте «медленный магазин» это видно: кнопки становятся активными с задержкой, и тест всё равно проходит — без единого `waitForTimeout`.
:::

:::tech Как запускается тест в этом приложении
Runner сохраняет ваш код во временную папку как `student.spec.ts`, поднимает учебный магазин на свободном порту и запускает `playwright test` с `baseURL` этого магазина, одним worker, без повторов, с таймаутом теста 10 с и assertion — 3 с. Результат берётся из JSON-отчёта Playwright. Для проверки задания тот же код запускается несколько раз: на исправном магазине и на вариантах с дефектами.
:::

:::interview
**Вопрос:** «Что делает тест полезным?» **Ответ по сути:** он проверяет наблюдаемый результат, важный пользователю, проходит на исправной системе и падает, когда этот результат нарушен; при падении сообщение показывает, что ожидалось и что получено. Тест без проверки или с проверкой «страница открылась» почти ничего не доказывает.
:::
