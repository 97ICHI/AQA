:::why
Если один тест положил товар в корзину, а следующий увидел эту корзину непустой, результаты зависят от порядка запуска — такие тесты падают «иногда». Playwright защищает от этого на уровне браузера: каждый тест получает свою изолированную сессию. В этом уроке вы разберёте, как устроены браузер, контекст и страница, и проверите, что корзины разных посетителей магазина не смешиваются.
:::

## Три уровня

Playwright управляет браузером через три вложенных объекта.

1. **[[pw-browser|Browser]]** — запущенный процесс браузера (например, Chromium). Запуск дорогой: сотни миллисекунд. Поэтому раннер запускает браузер один раз на [[worker|воркер]] и отдаёт его всем тестам этого воркера.
2. **[[browser-context|BrowserContext]]** — изолированная сессия внутри браузера, как отдельный профиль или окно инкогнито. У каждого контекста свои cookies, `localStorage`, кэш и разрешения. Создать контекст дёшево — десятки миллисекунд.
3. **[[pw-page|Page]]** — одна вкладка внутри контекста. Вкладки одного контекста делят [[cookie|cookies]]: вошли в одной — вошли во всех.

```text
Browser (Chromium)
├── BrowserContext теста A  — свои cookies, своя корзина
│   ├── Page (вкладка 1)
│   └── Page (вкладка 2)    — та же сессия, что у вкладки 1
└── BrowserContext теста B  — ничего не знает о тесте A
    └── Page
```

## Что делает раннер для каждого теста

Fixture `page` — это вкладка в **новом** контексте. Раннер создаёт контекст перед тестом и закрывает его после. Поэтому:

- каждый тест начинается без cookies — гостем с пустой корзиной;
- вход, сделанный в одном тесте, не «перетекает» в другой;
- порядок запуска тестов не влияет на результат.

Учебный магазин хранит корзину на сервере и узнаёт посетителя по cookie `sid`. Новый контекст — новый `sid` — новая пустая корзина.

```ts tests/context.spec.ts
import { test, expect } from '@playwright/test';

test('две вкладки одного контекста делят корзину', async ({ page }) => {
  await page.goto('/');
  const card = page.getByRole('listitem').filter({ hasText: 'Блокнот A5' });
  await card.getByRole('button', { name: 'В корзину' }).click();
  await expect(page.getByTestId('cart-count')).toHaveText('1');

  const secondTab = await page.context().newPage();   // вторая вкладка того же контекста
  await secondTab.goto('/cart');
  await expect(secondTab.getByTestId('cart-count')).toHaveText('1');

  const cookies = await page.context().cookies();
  expect(cookies.map((c) => c.name)).toContain('sid');
});
```

`page.context()` возвращает контекст, которому принадлежит страница, а `context.newPage()` открывает в нём новую вкладку. `context.cookies()` читает cookies контекста.

:::try Посмотрите на общую сессию
Запустите тест. Вторая вкладка видит тот же товар, потому что открыта в том же контексте и отправляет тот же cookie `sid`.
:::

## Второй посетитель — второй контекст

Fixture `browser` даёт доступ к браузеру воркера. `browser.newContext()` создаёт ещё один изолированный контекст. В Playwright Test такой контекст получает настройки из `use` конфигурации, в том числе `baseURL`, поэтому `goto('/')` в нём работает.

```ts
const otherContext = await browser.newContext();
const otherPage = await otherContext.newPage();
// … шаги второго посетителя …
await otherContext.close();   // контекст, созданный вручную, закрываем сами
```

:::mistake
**Проверять изоляцию вкладкой того же контекста.** `page.context().newPage()` — тот же посетитель. Тест «второй посетитель видит пустую корзину» с такой вкладкой упадёт на исправном магазине, а если ожидание подогнать, он перестанет ловить дефект «одна корзина на всех».
:::

## Задание

```widget
{"type":"exercise","id":"m5-context-two-visitors"}
```

:::deep Почему не новый браузер на каждый тест
Новый браузер на каждый тест дал бы ту же изоляцию, но стоил бы намного дороже. Контекст изолирует хранилище и сеть так же надёжно, как отдельный профиль, а создаётся быстро. Это главная причина, почему в Playwright принято «один контекст на тест», а браузер переиспользуется. Изоляция касается браузера: если тесты меняют общие данные на сервере (например, остаток товара на складе), контексты от этого не защищают — про данные будет отдельный урок.
:::

:::tech Настройки контекста
`browser.newContext(options)` принимает те же опции, что и `use` в конфигурации: `baseURL`, `viewport`, `locale`, `timezoneId`, `storageState` (готовые cookies и `localStorage`), `permissions`, `httpCredentials` и другие. Fixture `context` в тесте — это контекст, которому принадлежит `page`. Если нужно два пользователя сразу, создают второй контекст через `browser.newContext()`; страница из него не закрывается раннером автоматически, поэтому контекст закрывают в конце теста.
:::

:::interview
**Вопрос:** «Чем BrowserContext отличается от Page и зачем он нужен в тестах?» **Ответ по сути:** Page — вкладка, Context — изолированная сессия (cookies, хранилище, кэш, разрешения), в которой живут вкладки. Раннер создаёт новый контекст на каждый тест, поэтому тесты не делят состояние браузера и не зависят от порядка. Для двух пользователей в одном тесте создают два контекста.
:::
