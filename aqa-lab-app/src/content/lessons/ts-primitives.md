:::why
Почти всё, что проверяет тест, — это строки и числа: название товара, текст статуса, сумма заказа. Ошибки на этом уровне — `'390'` вместо `390`, `undefined` вместо названия — встречаются постоянно. Разберём основные виды значений и то, как они ведут себя.
:::

## Пять основных видов значений

Простые значения называют [[js-primitive|примитивами]]:

| Вид | Пример | Тип в TypeScript |
|---|---|---|
| Строка | `'Блокнот A5'`, `"Ручка"` | `string` |
| Число | `390`, `0.5`, `-10` | `number` |
| Логическое значение | `true`, `false` | `boolean` |
| «Пусто, задано явно» | `null` | `null` |
| «Значения нет» | `undefined` | `undefined` |

Узнать вид значения во время выполнения можно оператором `typeof`: `typeof 390` даёт `'number'`, `typeof 'abc'` — `'string'`.

## Строки

Строку пишут в одинарных `'…'`, двойных `"…"` или обратных кавычках `` `…` ``. Обратные кавычки создают [[template-literal|шаблонную строку]]: в неё можно подставлять значения через `${…}`.

```ts tests/data/labels.ts
const title = 'Блокнот A5';
const price = 390;
const label = `${title} — ${price} ₽`;       // 'Блокнот A5 — 390 ₽'
const sameLabel = title + ' — ' + price + ' ₽';  // то же самое через +
```

Строки сравниваются посимвольно: `'Итого: 780 ₽'` и `'Итого: 780₽'` — разные строки. В тестах именно это часто становится причиной падения: лишний пробел или другой символ тире.

Полезные свойства и методы строки: `label.length` — длина, `label.includes('390')` — содержит ли подстроку, `label.trim()` — без пробелов по краям, `label.toLowerCase()` — в нижнем регистре.

## Числа

В JavaScript один числовой тип для целых и дробных. Две особенности, которые встречаются в тестах:

- Дробные числа хранятся приближённо: `0.1 + 0.2` даёт `0.30000000000000004`. Поэтому деньги часто считают в копейках (целыми числами) или округляют.
- `Number('390')` превращает строку в число `390`, а `Number('390 ₽')` — в `NaN` («не число»). `NaN` — тоже значение типа `number`, и оно не равно даже самому себе.

## null и undefined

Оба означают «значения нет», но по-разному:

- `undefined` ([[null-undefined|«значения нет»]]) — значение не задано: переменная объявлена без значения, у объекта нет такого поля, функция ничего не вернула.
- `null` — пустоту указали явно: «промокода нет», «город не указан». В JSON от сервера встречается `null`, а не `undefined`.

```ts tests/data/order.ts
const order = { id: 17, promoCode: null };
console.log(order.promoCode);   // null — поле есть, значение пустое
// order.comment не существует → было бы undefined
```

Попытка прочитать свойство у `null` или `undefined` — самая частая [[runtime-error|ошибка выполнения]] в тестах: `TypeError: Cannot read properties of undefined`.

## Задание

В задании код уже обёрнут в **функцию** — именованный кусок кода, который получает значения (здесь `title` и `price`) и возвращает результат после слова `return`. :::mistake Сравнивать текст на странице «на глаз»
`'Итого: 780 ₽'` на странице может содержать неразрывный пробел перед `₽`. Визуально он не отличается от обычного, но строки не равны. Если тест падает на «одинаковых» строках, проверьте пробелы и тире.
:::

:::deep Почему `0.1 + 0.2 !== 0.3`
Числа хранятся в двоичном формате с плавающей точкой (IEEE 754). `0.1` в двоичной записи — бесконечная дробь, как `1/3` в десятичной, и сохраняется с округлением. Ошибки округления складываются. Для денег надёжнее целые копейки или явное округление при сравнении.
:::

:::tech Какие ещё примитивы есть
Кроме перечисленных, в JavaScript есть `bigint` (целые произвольной длины, `10n`) и `symbol` (уникальные идентификаторы). В тестах они почти не встречаются.
:::

:::interview
**Вопрос:** «Чем `null` отличается от `undefined`?» **Ответ по сути:** `undefined` — значение не задано (нет поля, не передан аргумент, функция ничего не вернула); `null` — пустота, указанная явно. JSON поддерживает `null`, но не `undefined`. При проверке API это важно: «поле есть со значением null» и «поля нет» — разные ответы.
:::
