:::why
Всё, что делает страница магазина, — поиск, корзина, вход, заказ — это обмен сообщениями с сервером по HTTP. Тестировщик, который умеет прочитать запрос и ответ, быстро понимает, где сломалось: в браузере или на сервере. А API-тесты — это и есть отправка запросов и проверка ответов.
:::

## Запрос и ответ

[[http|HTTP]] устроен как диалог: клиент (браузер или тест) отправляет **запрос**, сервер возвращает **ответ**. Каждый запрос независим: сервер не «помнит» прошлый разговор сам по себе — как он узнаёт пользователя, разберём в уроке про cookies.

Нажатие «В корзину» в учебном магазине отправляет такой запрос:

```http
POST /api/cart HTTP/1.1
Host: 127.0.0.1:3000
Content-Type: application/json
Cookie: sid=4f1c…

{"productId":3,"qty":1}
```

Из чего он состоит:

- **метод** — [[http-method|что сделать]]: `GET` — получить, `POST` — создать или выполнить действие, `PUT`/`PATCH` — изменить, `DELETE` — удалить;
- **путь** — с каким ресурсом: `/api/cart`. После `?` может идти строка запроса с [[query-parameter|параметрами]]: `/api/products?q=Блокнот`;
- **[[http-header|заголовки]]** — служебные пары «имя: значение». `Content-Type` говорит, в каком формате тело, `Cookie` передаёт данные сессии;
- **[[http-body|тело]]** — сами данные. Здесь это [[json|JSON]]. У `GET`-запросов тела обычно нет.

Ответ сервера:

```http
HTTP/1.1 200 OK
Content-Type: application/json; charset=utf-8

{"items":[{"productId":3,"title":"Блокнот A5","price":390,"qty":1}],"total":390,"count":1}
```

В нём [[status-code|код ответа]] (`200` — успешно), заголовки и тело. Скрипт страницы берёт из тела `count` и пишет его в счётчик корзины.

## Что проверять в ответе

API-тест проверяет ответ по слоям — от общего к частному:

1. **Код ответа.** Тот ли результат: успех, отказ, «не найдено»?
2. **Заголовки.** Например, `Content-Type: application/json` — иначе клиент не разберёт тело.
3. **Тело.** Есть ли нужные поля, правильные ли значения и **типы**: `"price": 390` (число) и `"price": "390"` (строка) — разные вещи. Код, который складывает цены, на строках получит `"390" + "590" = "390590"`.

## Запрос из теста

В Playwright запросы отправляют через фикстуру `request` — браузер для этого не нужен:

```ts tests/products-api.spec.ts
import { test, expect } from '@playwright/test';

test('поиск товара через API', async ({ request }) => {
  const res = await request.get('/api/products', { params: { q: 'Блокнот' } });
  expect(res.status()).toBe(200);
  expect(res.headers()['content-type']).toContain('application/json');
  expect(await res.json()).toEqual([
    { id: 3, sku: 'NOTE-A5', title: 'Блокнот A5', price: 390, stock: 40 },
  ]);
});
```

`params` превращается в строку запроса `?q=…` с правильным кодированием. `res.json()` разбирает тело. `toEqual` сравнивает объекты по содержимому — включая типы значений.

## Где посмотреть запросы браузера

:::deep Кодирование URL
В URL допустим ограниченный набор символов. Пробел, кириллица, `&`, `=`, `?` в значении параметра нужно закодировать: `Чай & кофе` → `%D0%A7%D0%B0%D0%B9%20%26%20%D0%BA%D0%BE%D1%84%D0%B5`. Без кодирования `&` разорвёт параметр на два. `encodeURIComponent` кодирует значение одного параметра; `URLSearchParams` и опция `params` в Playwright делают это автоматически (пробел они кодируют как `+`, что для строки запроса равнозначно).
:::

:::tech HTTP без состояния и HTTPS
HTTP не хранит состояние между запросами: всё нужное сервер получает в самом запросе — в пути, заголовках, теле, cookie. Поверх соединения обычно работает TLS — тогда это [[https-tls|HTTPS]]: содержимое зашифровано, но структура сообщения та же. Современные версии HTTP/2 и HTTP/3 передают данные иначе (в двоичном виде, несколькими потоками), но метод, путь, заголовки, тело и код ответа остаются теми же понятиями.
:::

:::interview
**Вопрос:** «Из чего состоят HTTP-запрос и ответ?» **Ответ по сути:** запрос — метод, URL (путь и параметры), заголовки, необязательное тело; ответ — код состояния, заголовки, тело. В API-тесте проверяю код, ключевые заголовки (Content-Type), структуру и типы полей тела, а для изменяющих запросов — ещё и итоговое состояние системы.
:::
