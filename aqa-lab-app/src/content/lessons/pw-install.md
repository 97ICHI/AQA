:::why
Прежде чем писать тесты, их нужно где-то запускать. Если проект собран неаккуратно, вы будете тратить время на «у меня не запускается» вместо проверки магазина. В этом уроке вы поставите всё нужное, разберёте, из каких файлов состоит проект, и запустите первый тест.
:::

## Что нужно установить

Тесты Playwright на TypeScript выполняются программой **Node.js** — средой, которая запускает JavaScript вне браузера. Вместе с Node.js ставится менеджер пакетов `npm` и утилита `npx`, которая запускает команды из установленных пакетов.

1. **Node.js** — актуальная LTS-версия (с долгой поддержкой) с сайта nodejs.org или через менеджер версий. Проверьте установку:

```bash
node --version
npm --version
```

2. **Playwright** — проще всего создать проект мастером. В пустой папке выполните:

```bash
mkdir shop-tests && cd shop-tests
npm init playwright@latest
```

Мастер задаст несколько вопросов: TypeScript или JavaScript (выбирайте TypeScript), папка для тестов (`tests`), добавить ли workflow для GitHub Actions и установить ли браузеры. Он установит пакет `@playwright/test`, создаст конфигурацию и пример теста.

3. **Браузеры.** Playwright управляет не браузером, установленным у вас в системе, а своими сборками Chromium, Firefox и WebKit — это [[playwright-browsers|браузеры Playwright]]. Если мастер их не скачал или вы обновили Playwright, выполните:

```bash
npx playwright install            # все три браузера
npx playwright install chromium   # только Chromium — быстрее
```

На Linux (и в CI) браузерам нужны системные библиотеки; их ставит флаг `--with-deps`.

:::warn
Каждая версия `@playwright/test` рассчитана на свои сборки браузеров. Если после обновления пакета тест падает с сообщением, что исполняемый файл браузера не найден, и предлагает запустить `npx playwright install`, — так и сделайте. Это не дефект магазина и не ошибка в тесте.
:::

## Из чего состоит проект

После мастера папка выглядит примерно так:

```text
shop-tests/
├── package.json          # зависимости и скрипты проекта
├── package-lock.json     # точные версии всех пакетов
├── playwright.config.ts  # конфигурация раннера
├── tests/
│   └── example.spec.ts   # пример теста
└── node_modules/         # установленные пакеты (в git не кладут)
```

После запуска появятся ещё две папки: `test-results/` (артефакты упавших тестов) и `playwright-report/` (HTML-отчёт). Их тоже не хранят в git.

Тестовые файлы называются `*.spec.ts` — по этому суффиксу раннер их находит. Главный файл настроек — [[playwright-config|конфигурация]]. Для учебного магазина минимальная версия выглядит так:

```ts playwright.config.ts
import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  testDir: './tests',
  timeout: 30_000,               // предел на один тест
  expect: { timeout: 5_000 },    // предел на одну проверку
  retries: process.env.CI ? 2 : 0,
  reporter: 'html',
  use: {
    baseURL: 'http://127.0.0.1:3000',
    trace: 'on-first-retry',
  },
  projects: [
    { name: 'chromium', use: { ...devices['Desktop Chrome'] } },
  ],
});
```

Разберём главное:

- `testDir` — где искать тесты;
- `timeout` и `expect.timeout` — сколько ждать тест целиком и одну проверку (подробно — в уроке о таймаутах);
- `use.baseURL` — [[base-url|базовый адрес]]: `page.goto('/cart')` превратится в `http://127.0.0.1:3000/cart`;
- `projects` — в каких браузерах запускать; здесь только Chromium;
- `retries` — повторы упавших тестов; локально их лучше выключить, чтобы видеть нестабильность сразу.

Учебный магазин можно поднять у себя: в папке AQA Lab выполните `node runner/shop.mjs` — он запустится на `http://127.0.0.1:3000`.

## Первый запуск

```bash
npx playwright test                     # все тесты, без окна браузера
npx playwright test tests/catalog.spec.ts
npx playwright test --headed            # с видимым окном
npx playwright test --project=chromium  # только один проект
npx playwright show-report              # открыть HTML-отчёт
```

По умолчанию браузер запускается в [[headless|режиме без окна]]: так быстрее, и так тесты работают в CI. Флаг `--headed` показывает окно — удобно, когда вы только учитесь.

Самый короткий осмысленный тест магазина проверяет, что каталог открылся:

```ts tests/catalog.spec.ts
import { test, expect } from '@playwright/test';

test('каталог открывается', async ({ page }) => {
  await page.goto('/');
  await expect(page).toHaveTitle(/Учебный магазин/);
  await expect(page.getByRole('heading', { name: 'Каталог' })).toBeVisible();
});
```

:::try Запустите первый тест
Нажмите «Запустить»: runner выполнит этот файл настоящим Playwright на исправном магазине. Потом замените `'Каталог'` на `'Корзина'` и запустите снова, чтобы увидеть, как выглядит падение.
:::

```widget
{"type":"playground","lang":"pw","title":"Первый тест: каталог открывается","variant":"ok","code":"import { test, expect } from '@playwright/test';\n\ntest('каталог открывается', async ({ page }) => {\n  await page.goto('/');\n  await expect(page).toHaveTitle(/Учебный магазин/);\n  await expect(page.getByRole('heading', { name: 'Каталог' })).toBeVisible();\n});\n","recorded":{"variant":"Исправный магазин","output":"✓ каталог открывается (254 мс)"}}
```

:::happened
Раннер нашёл файл, запустил браузер, создал для теста чистую страницу, открыл `/` (с учётом `baseURL`) и выполнил две проверки: заголовок вкладки содержит «Учебный магазин», а на странице видим заголовок «Каталог». Обе выполнились — тест зелёный. Если заменить текст заголовка, проверка `toBeVisible` будет ждать до таймаута и упадёт с сообщением, какой локатор не нашёлся.
:::

:::mistake
**Запуск из «не той» папки.** `npx playwright test` ищет конфигурацию в текущей папке. Если запустить команду из родительской папки, раннер не найдёт `playwright.config.ts` и тесты (или возьмёт чужие настройки). Запускайте из корня проекта — там, где лежит `package.json`.
:::

:::deep Почему версию Playwright фиксируют
В `package.json` версия может быть записана как `^1.58.2` — это разрешает обновление до любой 1.x. Точные версии фиксирует `package-lock.json`, а команда `npm ci` ставит ровно их. В CI используют именно `npm ci`: иначе в один день тесты запустятся на другой версии Playwright с другими браузерами, и падение будет не из-за вашего изменения. Обновление Playwright — отдельное осознанное изменение: поднять версию, выполнить `npx playwright install`, прогнать тесты.
:::

:::tech Ручная установка без мастера
Мастер не обязателен. В существующем проекте достаточно `npm install -D @playwright/test`, затем `npx playwright install chromium` и создать `playwright.config.ts` вручную. Проверить версию: `npx playwright --version`. Браузеры по умолчанию кладутся в общий кэш пользователя (на Linux — `~/.cache/ms-playwright`), поэтому их не нужно скачивать для каждого проекта заново; путь можно переопределить переменной окружения `PLAYWRIGHT_BROWSERS_PATH`.
:::

:::interview
**Вопрос:** «Тесты прошли локально, а в CI падают с ошибкой запуска браузера. Что проверите?» **Ответ по сути:** что в CI ставятся те же версии пакетов (`npm ci` по lock-файлу), что браузеры установлены именно для этой версии Playwright (`npx playwright install --with-deps`) и что в контейнере есть системные зависимости. Это проблема окружения, а не дефект приложения.
:::
