:::why
Проверить все возможные значения нельзя: количество товара может быть любым числом, сумма заказа — тоже. Нужно выбрать несколько значений так, чтобы они поймали как можно больше ошибок. Для этого есть две простые техники — классы эквивалентности и граничные значения.
:::

## Классы эквивалентности

Правило: «в корзину можно положить от 1 до 10 штук одного товара, количество — целое число».

Попробуйте 3, 5 и 7 штук. Скорее всего, программа обработает их одинаково — одной и той же веткой кода. Проверять все три почти бесполезно: если 5 работает, то и 7 работает.

Значения, которые система обрабатывает одинаково, образуют **класс эквивалентности**. Идея [[equivalence-partitioning|разбиения на классы]]: из каждого класса достаточно одного представителя.

Для правила о количестве классы такие:

| Класс | Пример | Ожидание |
|---|---|---|
| меньше допустимого | 0, −1 | отказ |
| допустимое | 5 | можно |
| больше допустимого | 15 | отказ |
| не целое | 2.5 | отказ |

Четыре значения вместо бесконечности. Обратите внимание на последний класс: «целое» — тоже часть правила, и его легко забыть.

## Границы

Классы соседствуют друг с другом, и на стыке — [[boundary-value-analysis|границе]] — ошибки встречаются чаще всего. Программист пишет `qty > 1` вместо `qty >= 1` или `qty < 10` вместо `qty <= 10`. Такая ошибка сдвигает границу на единицу, и значения из середины классов её не видят: 5 по-прежнему можно, 15 по-прежнему нельзя.

Поэтому для каждой границы берут **пару значений**: на самой границе и сразу за ней.

```text
           отказ  │      можно       │  отказ
       ... -1   0 │ 1   2 ...  9  10 │ 11  12 ...
                ▲   ▲              ▲    ▲
               за  на             на   за
```

Для правила «от 1 до 10» это 0 и 1, 10 и 11. Вместе с представителями классов (5 и 2.5) получается шесть проверок, которые ловят и «сдвиг на единицу», и «забытое условие».

:::note
Иногда к паре добавляют третье значение — «перед границей» (2 и 9). Оно полезно, когда границу задают сложной формулой. Для простых сравнений достаточно пары «на границе / за границей».
:::

## Пример в коде

Правило доставки: 299 ₽; бесплатно, если сумма товаров **от 3000 ₽ включительно**. Граница одна — 3000. Значения: 2999 (за границей, платно) и 3000 (на границе, бесплатно). Тесты ниже написаны для тренажёра: `test(название, функция)` объявляет тест, `expectEq(факт, ожидание)` — проверка.

```ts tests/shipping.test.ts
import { shippingCost } from './app';

test('2999 ₽ — доставка 299 ₽', () => expectEq(shippingCost(2999), 299));
test('3000 ₽ — доставка бесплатна', () => expectEq(shippingCost(3000), 0));
```

Слово «включительно» в требовании решает, какое ожидание у значения 3000. Если требование этого не говорит — это вопрос к аналитику, а не повод угадать.

:::warn
Для денег «за границей» означает минимальный шаг суммы. Если цены бывают с копейками, рядом с 3000 стоит 2999,99, а не 2999. Шаг выбирают по требованию и по тому, как система хранит значения.
:::

:::try Поймайте ошибки на границах
Стартовые тесты проверяют 5, 100 и 500 — значения из середины классов. Они проходят и на исправной версии, и на всех шести сломанных. Добавьте проверки так, чтобы каждая сломанная версия была поймана.
:::

```widget
{"type":"exercise","id":"m2-qty-boundaries"}
```

:::happened
Каждая сломанная версия отличается от исправной одним символом: `>=` стал `>`, `<=` стал `<`, `>= 3000` стал `> 3000`, исчезла проверка на целое. Ни одно «срединное» значение этого не видит. Пары «на границе / за границей» — 0/1, 10/11, 2999/3000 — ловят сдвиги, а 2.5 — забытый класс. Шесть-семь хорошо выбранных значений находят то, что не нашли бы сотни случайных.
:::

:::deep Классы бывают не только числовыми
Классы эквивалентности строятся для любых входных данных. Для промокода: верный код, неверный код, пустое поле, код в другом регистре. Для email: обычный адрес, без `@`, с пробелами, очень длинный. Для статуса заказа: каждый статус — свой класс. Если несколько условий действуют вместе (сумма и промокод, роль и статус), классы комбинируют таблицей решений — это следующий шаг техники.
:::

:::tech Таблица значений вместо копирования тестов
Когда значений много, их оформляют массивом и генерируют тесты в цикле:

```ts tests/qty.test.ts
const cases: [number, boolean][] = [[0, false], [1, true], [10, true], [11, false], [2.5, false]];
for (const [qty, ok] of cases) {
  test(`qty=${qty} → ${ok}`, () => expectEq(isValidQty(qty), ok));
}
```

Имя теста включает значение, поэтому в отчёте сразу видно, на какой границе ошибка. Такой подход называют data-driven; в Playwright он разбирается в уроке о параметризации.
:::

:::interview
**Вопрос:** «Поле принимает возраст от 18 до 65. Какие значения проверите?» **Ответ по сути:** классы: меньше 18, 18–65, больше 65, нечисловое/дробное/пустое. Границы: 17 и 18, 65 и 66. Плюс представитель середины (например, 30). Уточню, включительны ли границы и какой шаг значения (целые годы или дата рождения).
:::
