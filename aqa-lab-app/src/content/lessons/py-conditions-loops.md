:::why
Тестовые данные редко бывают идеальными: в выгрузке встречаются товары с отрицательной ценой, заказы без позиций, пользователи без email. Условия и циклы позволяют пройти по тысяче записей и найти те, что нарушают правила, — за секунду и без ошибок внимательности.
:::

## Условие if

`if` выполняет блок кода, только если условие истинно. Блок выделяется **отступом** (4 пробела) — в Python это часть синтаксиса, а не оформление:

```py tests/rules.py
stock = 0
if stock > 10:
    label = "в наличии"
elif stock > 0:
    label = "мало"
else:
    label = "нет в наличии"
print(label)   # нет в наличии
```

`elif` проверяется, только если предыдущие условия ложны; `else` — когда не подошло ничего.

### Истинность значений

В условии можно использовать не только `bool`. «Ложными» считаются `False`, `None`, `0`, `0.0`, пустая строка `""`, пустой список `[]` и пустой словарь `{}`; всё остальное — «истинно». Поэтому `if not item.get("title"):` ловит сразу и отсутствующий ключ, и пустое название.

Но осторожно: `if not price:` сработает и для `None`, и для бесплатного товара с ценой `0`. Если важно отличить «нет значения» от нуля, пишут явно: `if price is None:`.

## Цикл for

`for` проходит по элементам коллекции:

```py tests/check_items.py
items = [
    {"sku": "NOTE-A5", "price": 390, "qty": 2},
    {"sku": "MUG-01", "price": 690, "qty": 0},
]

for item in items:
    if item["qty"] <= 0:
        print("плохое количество:", item["sku"])
```

Полезные помощники: `range(5)` — числа 0…4; `enumerate(items)` — пары (номер, элемент), удобно для сообщений «строка 3»; `zip(a, b)` — попарный обход двух списков. `break` прерывает цикл, `continue` переходит к следующему элементу.

`while` повторяет блок, пока условие истинно. В тестах он нужен редко — например, для ожидания с таймаутом; основной инструмент — `for`.

## Генератор списка

Частый шаблон «пройти по списку, отобрать и преобразовать» записывается одной строкой — [[list-comprehension|генератором списка]]:

```py tests/check_items.py
bad_skus = [item["sku"] for item in items if item["qty"] <= 0]
total = sum(item["price"] * item["qty"] for item in items)
all_positive = all(item["price"] >= 0 for item in items)
```

`sum()`, `all()` (все истинны), `any()` (хотя бы один) и `min()`/`max()` принимают такие выражения напрямую. Генератор списка читается так: «sku каждого item из items, если qty ≤ 0». Если условие сложное или нужен не только результат, но и сообщения, обычный `for` понятнее.

:::deep Собрать все ошибки или упасть на первой
В тесте `assert` останавливает выполнение на первом расхождении. Для проверки большого набора данных это неудобно: исправили одну запись — упало на следующей. Практичнее собрать список проблем циклом и сделать одну проверку в конце: `assert problems == [], "\n".join(problems)`. Тот же принцип реализуют soft assertions в Playwright.
:::

:::tech Изменение списка во время обхода
Удалять элементы из списка внутри `for` по этому же списку нельзя: индексы сдвигаются, и часть элементов пропускается без ошибки. Вместо этого строят новый список: `items = [i for i in items if i["qty"] > 0]`. Для словаря изменение размера во время обхода — ошибка `RuntimeError: dictionary changed size during iteration`.
:::

:::interview
**Вопрос:** «Какие значения в Python считаются ложными и какая ловушка с этим связана?» **Ответ по сути:** `False`, `None`, ноль, пустые строка и коллекции. Ловушка — `if not value` не отличает «нет значения» от нуля или пустой строки: цена 0 окажется «отсутствующей». Когда это важно, пишут `if value is None`.
:::
