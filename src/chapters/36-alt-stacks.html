Альтернативные стеки

Справочная глава: как принципы учебника выглядят в Python + pytest + Playwright, Java + Selenium + JUnit 5 + REST Assured и Cypress. Не самостоятельный курс, а карта соответствий для тех, кто встретит другой стек на проекте или собеседовании.

≈ 6 мин чтенияM
Опирается на: Архитектура PlaywrightАвтоматизация API
Основная идея

Инструменты меняются, принципы остаются: устойчивые локаторы, ожидание состояния, изоляция через фикстуры, слой страниц и клиентов, данные под контролем, тесты в CI. Зная их на одном стеке, на другом нужно выучить синтаксис и особенности, а не автоматизацию заново.

Цель главы: сопоставлять понятия основного стека с альтернативными и понимать ключевые отличия при выборе инструмента.

Кратко

Принципы автоматизации переносимы между стеками; различаются способ управления браузером, модель ожиданий, система фикстур и экосистема.

Главное

  • Python + pytest + : тот же движок Playwright, фикстуры pytest (page, свои с yield), синхронный API по умолчанию.
  • Java + Selenium WebDriver: явные ожидания WebDriverWait, фабрика драйверов, JUnit 5/TestNG, Assured для API.
  • Cypress: тесты выполняются в браузере, цепочки команд с повторами, сильный DX для фронтенда, ограничения по вкладкам и доменам.
  • Сравнение по критериям: языки команды, браузеры, параллелизм, сеть, отчёты, порог входа, экосистема.
  • Python — отдельный backend-маршрут: pytest, Requests, Pydantic, Ruff; typing не заменяет runtime validation.

Термины

Playwright
Инструмент автоматизации браузеров Chromium, Firefox и WebKit с API для JS/TS, Python, Java и .NET.
Page Object Model
Паттерн: каждая страница описывается классом с локаторами и действиями пользователя; тесты используют эти методы и не знают о вёрстке.
Fixture
Именованный ресурс, который тест запрашивает в параметрах: фикстура готовит значение, передаёт его через use() и убирает за собой после теста.
Explicit Wait
Ожидание конкретного события или условия, заданного тестом: ответа сервера, URL, скачивания, значения через expect.poll.

Важно: Не переносите привычки механически: в Selenium нет автоожидания web-first проверок Playwright, а в Cypress команды — не , и async/await с ними не работает.

Python + pytest + Playwright#

Pythontests/test_cart.py
import re
from playwright.sync_api import Page, expect


def test_promo_reduces_total(page: Page, cart_with_product):
    page.goto("/cart")
    page.get_by_label("Промокод").fill("SALE10")
    page.get_by_role("button", name="Применить").click()
    expect(page.get_by_test_id("cart-total")).to_have_text("8 982 ₽")
    expect(page).to_have_url(re.compile(r"/cart"))
Pythontests/conftest.py
import uuid
import pytest
from playwright.sync_api import APIRequestContext, Playwright


@pytest.fixture(scope="session")
def api(playwright: Playwright) -> APIRequestContext:
    ctx = playwright.request.new_context(base_url="http://localhost:8080")
    yield ctx
    ctx.dispose()


@pytest.fixture
def cart_with_product(api: APIRequestContext):
    user = api.post("/api/users", data={"email": f"qa+{uuid.uuid4().hex[:8]}@example.com"}).json()
    yield user                       # код после yield — teardown
    api.delete(f"/api/users/{user['id']}")

Соответствия: фикстуры pytest с yield ≈ фикстуры с use; scope="session" ≈ Worker-фикстура (при pytest-xdist — на процесс); параметризация — @pytest.mark.parametrize; запуск — pytest --browser chromium -n 4.

Java + Selenium + JUnit 5 + REST Assured#

JavaCheckoutTest.java
import org.junit.jupiter.api.*;
import org.openqa.selenium.*;
import org.openqa.selenium.chrome.ChromeDriver;
import org.openqa.selenium.support.ui.*;
import java.time.Duration;

class CheckoutTest {
    WebDriver driver;
    WebDriverWait wait;

    @BeforeEach
    void setUp() {
        driver = new ChromeDriver();                      // Selenium Manager подберёт драйвер
        wait = new WebDriverWait(driver, Duration.ofSeconds(5));
    }

    @AfterEach
    void tearDown() { driver.quit(); }

    @Test
    void promoReducesTotal() {
        driver.get("https://staging.shop.example.com/cart");
        driver.findElement(By.cssSelector("[data-testid='promo-input']")).sendKeys("SALE10");
        driver.findElement(By.xpath("//button[normalize-space()='Применить']")).click();
        // явное ожидание состояния — аналог web-first assertion
        wait.until(ExpectedConditions.textToBe(By.cssSelector("[data-testid='cart-total']"), "8 982 ₽"));
    }
}
JavaOrdersApiTest.java
import static io.restassured.RestAssured.given;
import static org.hamcrest.Matchers.*;

class OrdersApiTest {
    @org.junit.jupiter.api.Test
    void createOrder() {
        given().baseUri("https://staging.shop.example.com")
               .contentType("application/json")
               .body("{\"productId\": 1, \"qty\": 2}")
        .when().post("/api/orders")
        .then().statusCode(201)
               .header("Location", matchesPattern("/api/orders/\\d+"))
               .body("status", equalTo("created"));
    }
}

Отличия, о которых важно помнить: пишется явно (WebDriverWait, ExpectedConditions), findElement ищет сразу и бросает NoSuchElementException, найденный WebElement может устареть (StaleElementReferenceException). распространён (часто с PageFactory), параллелизм и разные браузеры — через Selenium Grid или облачные фермы.

Cypress#

TypeScriptcypress/e2e/cart.cy.ts
describe('корзина', () => {
  it('промокод уменьшает сумму', () => {
    cy.intercept('POST', '/api/cart/promo').as('promo');
    cy.visit('/cart');
    cy.findByLabelText('Промокод').type('SALE10');   // Testing Library для Cypress
    cy.contains('button', 'Применить').click();
    cy.wait('@promo').its('response.statusCode').should('eq', 200);
    cy.get('[data-testid="cart-total"]').should('have.text', '8 982 ₽');
  });
});

Особенности: команды Cypress ставятся в очередь и выполняются позже — это не , поэтому async/await и обычные переменные для результатов команд не работают (используются .then и алиасы); should повторяет проверку до таймаута; тест работает внутри браузера, что упрощает доступ к приложению, но ограничивает работу с несколькими вкладками и доменами.

from pydantic import BaseModel, ConfigDict, Field

class Order(BaseModel):
    model_config = ConfigDict(strict=True)
    id: str
    quantity: int = Field(ge=1, le=10)
    total: int
    status: str

# response — requests.Response; проект должен передать session и base_url.
response = session.post(f'{base_url}/api/orders', json={'quantity': 2}, timeout=5)
assert response.status_code == 201
order = Order.model_validate(response.json())
assert order.total == 2000
assert order.status == 'created'

Pydantic проверяет данные во время выполнения. strict=True ограничивает неявное приведение, но каждое ограничение схемы задаётся явно. Requests синхронный: из TypeScript сюда не переносится. Декоратор оборачивает поведение функции; сохраняйте её метаданные через functools.wraps и не прячьте retries записи без анализа идемпотентности.

Для самостоятельного проекта добавьте fixture pytest с requests.Session, yield и cleanup, тесты негативных данных, Ruff, фиксированные зависимости и Allure. Пример выше не подтверждает выполнение Python-набора.

Как выбирать#

  1. Язык команды и продукта. Тесты, которые разработчики могут читать и править, живут дольше.
  2. Браузеры и платформы. Нужен ли реальный Safari, мобильные устройства, старые браузеры.
  3. Требования к сети и изоляции: перехват запросов, несколько пользователей, вкладки, домены.
  4. Инфраструктура: существующий CI, Grid, облачные фермы, отчётность (Allure есть для всех стеков).
  5. Прототип: несколько реальных сценариев на кандидатах — лучше любой сравнительной таблицы (AQA System Design).

Типичные ошибки#

Thread.sleep в Selenium вместо явных ожиданий

Тот же антипаттерн, что waitForTimeout: медленно и нестабильно.

async/await в Cypress

Команды Cypress не возвращают со значением; такой код ведёт себя непредсказуемо.

Смешивать несколько UI-фреймворков в одном проекте без причины

Два набора правил, два способа ожиданий, две инфраструктуры — двойная стоимость поддержки.

Что важно для собеседования#

MiddleВы переходите с Selenium + Java на Playwright + TypeScript. Что изменится в подходе к ожиданиям и изоляции?

Ответ

Явные WebDriverWait заменяются автоожиданием действий и web-first assertions; локаторы становятся ленивыми, нет StaleElementReferenceException. Изоляция — через на тест вместо нового драйвера; параллелизм и шардирование встроены вместо Grid. Появляются перехват сети, storageState и trace. Принципы POM, данных и CI остаются.

MiddleЧем модель выполнения Cypress отличается от Playwright?

Ответ

Cypress выполняет тесты внутри браузера, а команды ставит в очередь — это не , поэтому async/await к ним не применяется, результаты получают через .then и алиасы. управляет браузером из отдельного процесса по протоколу, команды — обычные Promise. Отсюда различия: несколько вкладок и доменов, контексты пользователей, языки, параллелизм.
